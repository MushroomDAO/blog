# 小红书图文帖模板（手机端）

给"博客文章 → 小红书图文笔记"这个转换定的固定结构。跟博客的差异不是"变短"，
是**手机竖屏、无超链接、进 feed 靠前 3 秒抓注意力**这三个约束决定的排版方式。

## 结构

1. **封面图**（第 1 张，决定点击率）
   - 竖版 3:4，常见尺寸 1242×1656 或 1080×1440
   - 大字标题 + 1 个视觉锚点（icon/截图/配色块），不要塞正文
   - 标题走博客同一条 hook，但压缩到 ≤20 字符（小红书标题输入框上限）

2. **内容卡片**（第 2 张起，3-6 张）
   - 每张卡一个独立论点，不是博客段落的直接截断
   - 复用 `pipeline/m3/renderer/xiaohongshu-renderer.js` 出的卡片视觉（页眉水印
     "🍄 原文发布于 blog.mushroom.cv" + 页脚品牌条已经内置，不用重做）
   - 图多文少：每卡正文控制在 40-80 字，靠加粗/emoji 项目符号分层，不整段堆文字

3. **正文/文案**（笔记描述框，≤1000 字）
   - 开头 1 句钩子，呼应封面标题，不要重复同一句话
   - 中间 3-5 条要点，一条一行，`emoji + 短句`，别写大段落
   - 结尾软 CTA：引导评论/收藏，不要求关注这种硬转化话术
   - 小红书正文里的链接不可点，**不要写 `[text](url)` 或裸 URL 当作可点击引导**
     ——只在最后一行提一句"完整版看主页链接/搜同名博客"，不追求这次跳转
   - 标签 3-6 个，放正文最后一行，不要夹在句子中间

## 示例（基于博客真实选题风格，不用"姐妹们/YYDS"这套网感话术）

> **封面标题**：AI 自己改代码，还会自己判断改坏了吗？
>
> **正文**：
> 让 AI 自己跑实验：改一次代码 → 跑 Benchmark → 变差就自动回滚。
>
> 🔁 核心思路：把"要不要保留这次修改"的判断权交给 benchmark 结果，不是靠人盯着
> 📉 变差自动回滚，省掉人工比对两次跑分的步骤
> 🧪 本质是给 AI agent 加了一层"自我验证"闭环，不是单纯改完就交
> 🔗 完整拆解看主页博客同名文章
>
> #AI Agent #开源工具 #Coding Agent #自动化实验

## 发布方式（当前可用）

- **图文帖**：`xhs post --title "..." --body "..." --images a.png b.png c.png --topic "..."`
  （`xhs` CLI 已认证，账号 Mushroom.cv，见 [[project_xhs_cookie_source]]）
- **视频**：`~/tools/social-auto-upload` 的 `sau xiaohongshu upload-video`
  （Playwright 浏览器自动化，**需要先手动扫码登录一次**：
  `cd ~/tools/social-auto-upload && .venv/bin/python sau_cli.py xiaohongshu login --account mushroom --headed`）
