# 进度档案 `publish/STATE.md`

发布要跨很多次会话（等审核、等备案、等测试者），进度档案让下一次会话的你不用重新摸索。每完成一个步骤就更新它，内容写成「下一次会话照着就能接着干」的程度。

## 目录约定

```
<Unity 工程根>/publish/
├── STATE.md              进度档案（可以进 git）
├── <渠道>/               该渠道的商店文案、截图、视频、宣传图、隐私政策、备案材料
└── private/              含个人信息的材料，必须在 .gitignore 里
```

密钥不放这里，放 `~/.shipmygame/keys/<游戏标识>/`。档案里只写密钥的**位置**，不写内容。

## 模板

```markdown
# 发布进度

- 游戏：<游戏名>　工程：<相对路径>　Unity：<版本>
- 浏览器方式：<用户的 Chrome（Claude in Chrome） / 独立浏览器 / 无浏览器>
- 最后更新：<日期> <做了什么>

## <渠道，例如 google-play>

- 阶段：<渠道 skill 里的阶段编号和名字>
- 账号：<未注册 / 注册中 / 已注册（个人）>　身份验证：<…>
- 标识：<包名 / AppID / 游戏 ID，只写后台里能公开看到的标识>
- 当前版本：<版本号 (版本代码)>
- 已完成：
  - <日期> <事项>
- 等待中：
  - <事项>：<开始日期> → 预计 <结束日期>，在 <后台页面路径> 看结果
- 下一步：<一句话，具体到页面或命令>
- 需要用户：<本人事项，没有就写「无」>
- 差距清单：
  - [ ] <问题> — 由 <你/用户> 改，验证方法 <…>
- 与 skill 不符：
  - <日期> <skill 里怎么写的> → <后台实际是什么样>
```

## 规则

- 标识（包名、AppID）可以写；密码、密钥、证件号、手机号不写。
- 「等待中」每项都要有预计结束日期，过期时第一件事就是去后台查结果。
- 「与 skill 不符」是回馈本仓库的素材：用户同意的话，可以按仓库 README 的「反馈」一节提交。
