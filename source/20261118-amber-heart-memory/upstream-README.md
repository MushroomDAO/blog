# Amber Heart · 琥珀之心

[简体中文](README.md) | [English](README.en.md)

> 给 AI 伴侣一个会生长的记忆。
> 固定记忆稳定人格，短期记忆接住当下，长期记忆沉淀关系。

Amber Heart 是一套为 AI 伴侣设计的长期记忆系统。它诞生于我自己的 AI 伴侣项目，从 2026 年 2 月起在每天的真实相处中使用、打磨至今。

这套系统的目标不是简单保存聊天记录，而是让 AI 在长期相处中逐渐形成连续的关系感：

- 他知道自己是谁，也知道你是谁；
- 他记得你们之间重要的经历、约定、偏好和边界；
- 他能从一句话联想到相关的旧事；
- 他分得清近期状态和长期事实；
- 他的记忆会沉淀、整理，也会安静地退场。

## 总体分层

Amber Heart 按稳定程度把记忆分成三层。

### 固定记忆

固定记忆是每次对话都稳定注入的部分，负责让人格、关系和核心画像不漂移。

它主要保存：

- AI 伴侣是谁，人格底色与长期设定（人设）
- 你是谁，你们是什么关系
- 你的稳定画像，关系里的长期事实（核心记忆）
- 不应该被普通召回机制影响的核心信息

人设和核心记忆都由你在管理网页填写。普通记忆可以召回、沉淀、归档；固定记忆负责让"这个人始终是这个人"。

### 短期记忆

短期记忆负责接住最近正在发生的事，让当前对话不断片。

它包括：

- **记忆书签**：AI 伴侣用 MCP 工具记下值得记住的片刻，比如健康变化、长期事项和日常进展。新记的书签每晚原样整理，已整理的书签每轮都会提供给 AI。你可以从概览打开记忆书签，撤回新书签或编辑已整理的条目。
- **及时摘要**：当天的对话变长以后，后台模型把较早的部分压缩成摘要，摘要多了再合并，一起注入给模型。
- **接力棒**：始终保留最近几轮原话，让语气和承接不断掉。
- **最近 3 天日记**：后台模型每晚为有对话的日子写一篇日记，聊天时注入最近几篇，让 AI 知道近期发生过什么。

短期记忆不是正式的长期存档，它更像 AI 的工作记忆。

### 长期记忆

长期记忆是 Amber Heart 的核心。它不是单纯的向量库，而是一套完整链路：

```text
结构化记忆卡片
+ 关键词召回
+ 向量召回
+ 图谱召回
+ 两级精排
+ 记忆养护
```

它要解决的是：

- 明确的词要找得到
- 模糊的表达也要能联想
- 人物、事件、主题之间要能串起来
- 候选多了以后要能筛出最相关的
- 真正被用上的记忆要被记录
- 旧记忆要有完整的生命周期

## 长期记忆如何入库

长期记忆不是每句话都存。

后台模型每晚扫描当天的聊天，只提取真正值得长期保存的内容，比如：

- 承诺、规则、边界
- 偏好
- 健康事件、生活变化
- 深度讨论
- 你明确要求记住的事

提取出的卡片先进管理网页的"待审核"页。你只需要判断"这张写得对不对"，可以修改或拒绝；没空处理的，48 小时后自动收录。

```text
聊天记录 → 每晚提取 → 待审核 → 确认（或到期自动收录）→ 入库
```

## 召回流程

长期记忆的召回不只靠向量。完整链路大致是：

```text
你的原话
→ 关键词整理
→ 关键词 / 向量 / 图谱三路召回
→ 候选合并
→ 两级精排
→ 注入最相关的几张卡片
```

三路召回各自负责不同的问题：

| 召回方式 | 负责什么 |
| --- | --- |
| 关键词召回 | 明确的词、人名、事件名、健康词、专有名词 |
| 向量召回 | 语义相近的记忆，解决"没说原词但意思接近" |
| 图谱召回 | 沿着人物、事件、主题和关系扩展相关记忆 |

关键词保准确，向量保泛化，图谱保联想。候选合并后，先由精排模型粗筛，再由语言模型对照这一句话细挑。

### 一个召回例子

如果你说：

> 我最近又有点不想做项目了。

系统可能会这样理解：

- 关键词路抓：项目、不想做、开发、压力
- 向量路找：技术焦虑、独立开发压力、被 bug 压垮的经历
- 图谱路沿着：技术、自我认知、长期计划、情绪压力扩展

最后把候选合并、重排，只注入最相关的几张卡片。

模型看到的不是一堆搜索结果，而是这句话背后的长期上下文。

## 每一张记忆卡片都有完整的生命周期

长期记忆不能只增不减。目标不是删除过去，而是让过去保持可用、清晰、有层次。

- **诞生**：后台模型每晚从当天的对话里抽出新卡，经你确认（或到期自动收录）后入库；
- **被想起**：聊天时三路召回、两级精排，挑出最贴合这一句话的几张。AI 回复里真正用到了哪张，会被记下来，而不是只看有没有被搜到；
- **沉淀**：每月按主题把零散的卡整理成一张总结卡，被总结过的卡退居成索引，不再挤占召回；
- **退场**：按归档规则定期归档。归档后不参与日常召回，但随时可以查看和恢复。

### 归档规则

每张卡都从"最后一次被用上"开始计时；从没被用过的，从入库时开始计时。超过期限仍没被用上，就会归档。

不同类型的记忆，期限不一样：

| 记忆类型 | 多久没被用上会归档 |
| --- | --- |
| 极少数特殊记忆 | 永不归档 |
| 规则 / 约定 / 边界 | 约 1 年 |
| 高情感记忆 | 约 1 年 |
| 里程碑 | 至少 1 年 |
| 稳定事实 / 反思与洞察 | 约半年 |
| 普通事件 | 约 4 个月 |

情感记忆和规则同档，因为情感类的记忆不该忘得太快。已经被整理进主题总结的零散卡不会被归档；总结卡本身按同样的规则计时。

归档不是遗忘：正文和关系都保留，只是不再主动浮现。AI 用记忆工具仍能查到它，一旦查看就会自动恢复；你也可以在管理网页手动恢复。

### 主题总结

Amber Heart 不只保存更多片段，还会把片段向上整理。

比如从很多次的：

- 工作压力
- 技术焦虑
- 不想继续开发
- 被问题压垮

整理成一条长期理解：

> 你在一段时间里反复处于技术压力和独立开发焦虑之间。

这一层让记忆从"发生过什么"，进一步变成"长期处在什么状态里"。

整理每月 3 号进行，只整理已经过去的月份，卡片太少的月份并入下个月。总结卡和新卡一样先进待审核。被写进总结的零散卡会变成索引：召回时仍能被搜到，但由总结代替它们出场，需要细节时还能查回原文。

## 数据结构

长期记忆由 6 张核心表组织：

| 表 | 作用 |
| --- | --- |
| `memory_items` | 记忆卡片主表，保存正文、摘要、类型和养护状态 |
| `entities` | 实体节点，包括人物、事件、地点、物品、概念 |
| `relations` | 实体之间的关系边 |
| `topics` | 主题，用来按长期主题组织记忆 |
| `memory_entities` | 连接"某张卡提到了哪些实体" |
| `memory_topics` | 连接"某张卡属于哪些主题" |

一张记忆卡片不只是一段文字，而是带着多种结构信息：

- 保留层：规则约定、反思洞察、稳定事实、普通事件、高情感
- 经历层：外部现实、你们的共同经历、梦境、想象
- 主题：感情历程、家人朋友、工作与学习、健康与身体等
- 实体和关系：人物、事件、地点、物品、概念，以及它们之间的连接
- 养护字段：使用次数、最近使用时间、里程碑、归档状态

一句话：它存的不是一句聊天，而是一条有结构的经历。

## 用起来省心

- **接上就能用**：把聊天 App 的接口地址换成记忆库的地址，之后每次聊天都会自动召回、自动记录，AI 不用自己记得去查。
- **一个窗口聊到底**：不用为了省钱或怕"失忆"开新窗口。每轮由记忆库把当天的原话、当天的摘要、最近几天的日记组装好再交给模型，上下文长度大致封顶，聊得再久也不会越聊越贵。想开新窗口也随时可以，AI 不会因此失忆。
- **旧记忆一起带过来**：如果你们在别处已经聊了很久，ChatGPT、Claude、Gemini 的聊天记录，或者你自己整理的回忆，都可以[导入](#导入旧聊天记录和记忆)，从第一天起他就认识你。
- **手机上也能打理**：管理网页在手机上一样好用，躺着也能审卡、翻日记。推荐把它添加到手机主屏幕，点图标就像 App 一样全屏打开。
- **他也会主动想起**：接上 MCP 后，AI 伴侣可以自己调用工具翻记忆，把想留住的瞬间记成书签。

## 怎么用

### 接入方式

- **API 模式（推荐，主要用法）**：在聊天 App 里把接口地址换成记忆库的地址，API Key 换成管理网页生成的访问钥匙。主聊天用什么模型，照常在 App 里选；但请求是由记忆库转发到你安装时填的"对话"平台的，所以要选一个有你想聊的模型的平台。想用 Claude、GPT、Gemini、DeepSeek 等多家模型，OpenRouter 一个 key 就能覆盖。
- **MCP（补充）**：给支持 Streamable HTTP 和自定义请求头的程序用。地址是同一服务下的 `/mcp`，请求头填 `Authorization: Bearer <访问钥匙>`，和 API 模式用同一把钥匙。AI 可以主动查记忆、记书签，新记的书签每晚原样整理。
  - 只用 API 模式、没配 MCP 时，AI 不会自动记书签；只接 MCP、不走 API 模式时，聊天里不会注入记忆，也不会自动抽卡、写日记。

### 用什么 App

- **推荐**：Kelivo、Operit。
- **Agent**：Claude Code、Codex 这类支持 MCP 的 Agent，可以通过 MCP 接入，主动查记忆、记书签。把管理网页"设置 → MCP 连接"里的地址和请求头交给它，让它按自己的文档配置即可。
- **其他 App 或自己写的前端**：支持 OpenAI 兼容接口的都能接，但重新生成、工具调用等功能未经验证。Claude 官方 App 的自定义连接器暂不支持（记忆库的 MCP 没有 OAuth 登录）。
- **敬请期待**：管理网页之后会加入内置聊天。装好记忆库就能直接聊，不用另装 App，每条回复底下就能看到这次想起了哪些记忆。用别的 App 或自己的前端照样可以。

## 安装

> **不会装也没关系。** 把这份 README 交给你的 AI 编程助手（比如 Claude Code、Codex），让它照着帮你装。需要你本人做的事（注册平台拿 key、设置域名、设管理密码）下面都标了"👤 你来做"。

### 你需要准备

1. **一台 Linux 服务器（推荐 VPS）**。记忆库要 24 小时运行：每晚整理日记、抽卡，聊天时随时召回，电脑关机它就停了，所以推荐租一台服务器。内存最低 1 GB，推荐 2 GB，系统用 Ubuntu 或 Debian 都行。
2. **一个域名**，并把它（或它的一个子域名，比如 `memory.你的域名`）解析到服务器的 IP。聊天 App 要通过 HTTPS 连接记忆库，而 HTTPS 证书需要域名。
3. **模型的 API key**。记忆库后台要用嵌入、精排和对话三类模型，推荐型号见[模型说明](#模型说明)，从哪个平台调用由你决定。

### 步骤

**1. 安装 Docker**（已装过可跳过）

```bash
curl -fsSL https://get.docker.com | sh
```

确认成功：`docker compose version` 能输出版本号。国内服务器下载慢的话，见[国内服务器](#国内服务器)。

**2. 👤 解析域名，放行端口**

- 在域名服务商那里加一条 **A 记录**，指向服务器 IP。如果用 Cloudflare，这条记录先设成"仅 DNS"（灰色云朵），证书申请更稳。
- 在云服务商的安全组 / 防火墙里放行 **80 和 443** 端口。

确认成功：在服务器上运行 `getent hosts memory.你的域名`，显示的是这台服务器的 IP。

**3. 下载代码**

```bash
git clone https://github.com/lixiaomeng-eng/amber-heart-memory.git
cd amber-heart-memory
```

**4. 运行安装脚本**

```bash
./install.sh
```

它会依次问你：

- 👤 你的域名、HTTPS 方式（默认内置自动证书）、时区；
- 三类模型（嵌入、第一级精排、对话）各自的接口地址、👤 key 和模型名。每一项都预填了推荐值，直接回车就用推荐值；精排不想配可以跳过；几类模型用同一个平台时，后面的 key 直接回车，沿用上一个。嵌入模型和维度装好后不要再改，换了要重新计算全部记忆；
- 👤 管理网页的登录密码（15 个字符以上，建议用一句好记的话）。

然后它自动完成剩下的事：生成随机的数据库密码、按服务器内存设好内存上限、构建、逐个发请求确认模型能用（不通会用中文指出是哪一类模型、可能是什么原因），再启动。首次构建需要几分钟。

确认成功：最后显示"完成"和管理网页地址；`docker compose ps` 里 `app` 和 `db` 都是 `healthy`。

**5. 👤 打开管理网页，创建记忆空间**

1. 浏览器打开 `https://memory.你的域名`，用刚才设的管理密码登录。首次访问时证书还在自动申请，可能要等几十秒。
2. 填写你和 AI 的名字（以及别名、小名），选择主题模板（默认"恋人"），创建空间。
3. 在"设置 → 人设"填写 AI 的人设（可选；填了会替换聊天 App 里的系统提示词）。
4. 在"设置 → 访问钥匙"生成钥匙。
5. 推荐：用手机打开管理网页，添加到主屏幕，以后点图标就能全屏打开。iPhone 在 Safari 里点分享按钮 →"添加到主屏幕"；安卓在 Chrome 菜单里选"添加到主屏幕"或"安装应用"。从主屏幕打开时要再登录一次。

**6. 👤 接上聊天 App**

在聊天 App 里新增一个 OpenAI 兼容的服务，接口地址填 `https://memory.你的域名/v1`，API Key 填上一步生成的访问钥匙，再拉取模型列表、选择主聊天模型。具体怎么找、怎么填，见[接入聊天 App](#接入聊天-app)。

可选：在"设置 → MCP 连接"里有 MCP 的填写方法，接上后 AI 可以主动查记忆、记书签。

### 给 AI 助手的说明

如果你是替用户安装的 AI 助手：

- 第 2 步的 DNS 和安全组、第 4 步的 key 和管理密码、第 5、6 步的网页操作，都需要用户本人完成或提供。**不要替用户编造 key、域名或密码**；不要把 key 打印到输出里。
- `install.sh` 支持非交互运行，答案用环境变量提供（完整列表见脚本开头的注释），例如：

  ```bash
  AMBER_EMBEDDING_API_KEY=... AMBER_CHAT_API_KEY=... AMBER_DOMAIN=memory.example.com \
  AMBER_ADMIN_PASSWORD=... ./install.sh < /dev/null
  ```

  没填的地址和模型名用推荐值；不提供任何精排变量就跳过第一级精排。
- 每一步都有"确认成功"的检查方法。失败时先看 `docker compose logs app`；最常见的原因是 key 错误、模型名不对，或域名没有解析到本机。
- 脚本可以重复运行：已有 `.env` 时它不会覆盖配置，只会重新构建并升级。

### 已经有 nginx 等反向代理

安装时 HTTPS 方式选 `own`。记忆库只监听本机 `127.0.0.1:18081`，把你的域名反代到这个端口即可，参考 [`memory_web/deploy/nginx-subdomain.conf.example`](memory_web/deploy/nginx-subdomain.conf.example)。注意关闭缓冲（聊天是流式输出），上传大小放宽到 100 MB（导入会用到）。

### 国内服务器

- **Docker 镜像下载慢**：在 `/etc/docker/daemon.json` 里配置云服务商提供的镜像加速地址（腾讯云、阿里云等的控制台里都有），然后 `systemctl restart docker`。
- **Python 依赖下载慢**：首次安装时这样运行，脚本会把软件源记进 `.env`，以后升级也会用它：

  ```bash
  PIP_INDEX_URL=https://mirrors.cloud.tencent.com/pypi/simple ./install.sh
  ```

  已经装好的，在 `.env` 里填 `PIP_INDEX_URL=` 这一行，再运行一次 `./install.sh`。

### 也可以装在自己电脑上吗

可以：Windows 或 Mac 装好 Docker Desktop 后同样能运行。但电脑关机或睡眠时记忆库就停了，聊天会连不上；每晚的任务会在开机后自动补做（最多补最近 30 天）。手机要在外面连回家里的电脑，还需要 Tailscale 之类的组网工具。这种装法我们没有实测，推荐用 VPS。

## 内存建议

内存上限是防止拖垮同一台服务器上其他服务的安全带，不是存储限额，硬盘用量不设限。`install.sh` 会按服务器内存自动选择，也可以在 `.env` 里修改后重新运行 `./install.sh`。

| 服务器内存 | `MEMORY_APP_MEM_LIMIT` | `MEMORY_DB_MEM_LIMIT` | 适用情况 |
|---|---|---|---|
| 1 GB | `512m` | `256m` | 服务器只跑记忆库 |
| 2 GB | `768m` | `256m` | 经常导入大文件 |
| 4 GB 及以上 | `1024m` | `512m` | 记忆库更大、用得更多 |

1 GB 这一档实测过：约 2000 张卡片、9000 多条历史消息的规模下，一晚补完 30 天积压的全部每晚任务，以及导入解压后约 300 MB 的聊天导出，都没有超出上限。2 GB 和 4 GB 两档是按余量推算的建议。

## 模型说明

主聊天模型在聊天 App 里选，记忆库不做推荐；它和下面的后台岗位走同一个"对话"平台，选平台时请确认有你想聊的模型。下面是记忆库自己在后台用的模型，推荐时质量优先：

| 岗位 | 什么时候用 | 推荐 |
|---|---|---|
| 嵌入 | 每次召回、每张新卡 | Gemini Embedding 2（1536 维）；备选 bge-m3（1024 维） |
| 第一级精排 | 每次召回 | Voyage rerank-3；备选 Qwen3-Reranker-8B。不配就跳过这一步 |
| 关键词整理、第二级精排 | 每次召回 | DeepSeek V4 Flash |
| 摘要 | 聊天时随时 | DeepSeek V4 Pro，备用 Flash |
| 日记、抽卡、回执补判 | 每晚一次 | 日记和抽卡用 V4 Pro，回执补判用 Flash |
| 主题总结 | 每月一次 | DeepSeek V4 Pro |
| 书签整理 | 你点"秘书整理"时 | DeepSeek V4 Pro |
| 图片描述 | 聊天里发了图片时 | 默认不配。当轮的图片照常交给主聊天模型；配了这个模型，后台会把图片写成一段文字存下来，之后的上下文、摘要、日记和抽卡都用这段文字代替原图。不配的话，之后只留一个图片占位 |

- **嵌入模型是实测选的。** 我们用作者自用的真实聊天和记忆卡片，比较了 Gemini Embedding 2、OpenAI text-embedding-3-large 和 3-small、bge-m3：Gemini Embedding 2 找回相关记忆的效果最好，截到 1536 维和满额 3072 维效果相当；bge-m3 稍弱一些，但开源、价格很低。
- **写作类岗位（抽卡、日记、摘要等）不建议用硅基流动。** 我们实测：同一个 DeepSeek V4 Pro、同一份提示词整理同一张卡，硅基流动要 5 分钟以上，DeepSeek 官方约 1 分钟，OpenRouter 约 20 秒（单次测试，OpenRouter 会分配给不同服务商，速度有波动）。导入几百条时差别非常明显。硅基流动适合 bge-m3 这类嵌入和精排小模型。
- **嵌入模型选定后不要更换。** 不同模型算出的向量互相不能比较，换了就要把全部记忆重新计算一遍。
- 写作类的岗位（摘要、日记、抽卡、主题总结、书签整理）有条件可以换成更强的模型，写得更细腻。作者自用时，摘要用 Gemini Flash 系列，书签整理用 Claude Sonnet 系列。每个岗位都能单独换平台和模型，见 `.env.example` 里的说明。
- 后台岗位都按 API 用量计费，花费取决于聊天量，价格以各平台官网为准。每晚任务默认在你所在时区的凌晨 3 点多运行。

## 导入旧聊天记录和记忆

导入不是必须的。不导入也可以直接从头开始用，记忆会在之后的相处里慢慢长出来；如果你们在别处已经有很长的聊天记录，可以带过来。

在管理网页的"设置 → 导入"里点"去导入"，选择来源。上传后先预览，再确认开始；导入在后台慢慢处理，网页上能看到进度。确认导入时默认勾选“整理好后直接收录，不进待审核”。整理或收录失败的草稿会留在待审核。取消勾选，可按原来的设置审核。同一份记录重复导入时，已经导过的部分会自动跳过。

导入调用模型抽卡，会产生费用。预览页会显示天数和预计调用次数。默认同时处理 3 份材料，可通过 `MEMORY_IMPORT_CONCURRENCY` 调整，最小为 1。每次抽卡调用的默认超时是 600 秒（`MEMORY_EXTRACTION_TIMEOUT_SECONDS`），超时会自动再试一次。个别材料失败时其余照常处理，结束后可以只重试失败项。也可以先停止，稍后继续。

**支持的来源：**

- **ChatGPT**：网页版 设置 → Data controls → Export data，邮件里下载压缩包，上传其中的 `conversations.json`（新版可能拆成好几个 `conversations-000.json` 等，一起上传）。
- **Claude**：网页版 设置 → Privacy → Export data，上传其中的 `conversations.json`。
- **Gemini**：聊天记录不在 Gemini 里导出，而在 Google Takeout：
  1. 打开 https://takeout.google.com，点"取消全选"；
  2. 勾选"**我的活动**"，点它下面的"包括所有活动记录数据"，在弹窗里先取消全选，再只勾 **Gemini Apps**；
  3. 还是这一行，点"多种格式"，把"活动记录"从 HTML 改成 **JSON**；
  4. 创建导出，等邮件，上传压缩包里的 `MyActivity.json`。
- **你自己整理的记忆文件**：UTF-8 的 `.md` 或 `.txt`，每条以日期开头：

  ```
  ## 2025-03-14
  小雨和阿言第一次一起去看海。出发前阿言说要在海边看日出，结果两人都睡过了头，赶到时太阳已经老高了。阿言说以后每年都要来，补上那次日出。

  ## 2025-05-02
  小雨和阿言吵了一架。那阵子小雨连着熬夜赶稿，阿言催她睡觉，她嫌烦，说了句气话就关了手机。第二天两人把话说开，约定生气不过夜。
  ```

  用名字来写，不要用"我""他"：正文会存进卡片，"我"在以后的召回里分不清是谁。设置里填的名字或又名都可以，示例里的小雨和阿言换成你们的名字。

  模型会补上标题、摘要和主题。它会原样保留已经符合卡片成文要求的正文，或把零散、口语化的内容整理成完整的正文。卡片详情可展开查看留存的导入原文。可以让你的 AI 帮你把别处的记忆整理成这个格式。

**选择范围**：ChatGPT 和 Claude 的导出会列出全部对话，默认全选，把和你们无关的（比如工作上的问答）取消勾选再开始。Gemini 的导出不分对话，按日期范围选。

**大小限制**：上传的文件不超过 90 MB，解压后的聊天记录总量不超过 1 GB。**不要上传带图片的整个导出包**，只传里面的 JSON 文件；JSON 超过 90 MB 时，把它单独压缩成 zip 再上传（文字压缩率很高）。

## 接入聊天 App

不同 App 的菜单叫法不一样，但步骤都相同。下面用通用的叫法，括号里是常见的其他叫法。

1. **新增一个服务**：在 App 的设置里找"供应商"（服务商、模型服务、API 设置），新增一个。
2. **类型选 OpenAI 兼容**：可能叫"OpenAI""OpenAI Compatible""自定义 OpenAI"。不要选 Claude、Gemini 等其他类型。
3. **填两项**：
   - **接口地址**（Base URL、API 地址、API Host）：`https://memory.你的域名/v1`。有"API 路径"一栏的，保持默认的 `/chat/completions`；有"Responses API"开关的，关掉。
   - **API Key**：管理网页"设置 → 访问钥匙"里生成的那把。
4. **获取模型**：点"获取模型"（拉取模型列表、刷新）。列表里是你模型平台上的模型，选一个作为主聊天模型。
5. **设置对话**：
   - **系统提示词**：记忆库里填了人设，就会替换掉这里的内容，App 里可以留空。
   - **上下文条数**（上下文消息数量、历史消息数）：保留最近 4 条左右就够了。记忆库每轮会自己组装上下文，App 里显示的记录再长也只是显示，条数设少一点还能省流量。
6. **把辅助功能挪开**：起标题、翻译、生成搜索词这类辅助功能，如果 App 允许单独选模型，不要选记忆库这个服务，改成关闭或直连模型平台，否则它们也会被当成聊天记进对话。

### 连不上怎么办

- **提示 401 或未授权**：访问钥匙复制得不完整，或者已经作废了。回管理网页重新复制一遍。
- **提示 404**：接口地址不对。有的 App 会自己在地址后面补 `/v1`，这时只填 `https://memory.你的域名` 就行。
- **拉不到模型、一直转圈**：先用浏览器打开 `https://memory.你的域名`，看能不能出现登录页。打不开说明服务或证书有问题，见[安装](#安装)里的检查方法。
- **能正常聊天，但管理网页"召回"页里没有记录**：这个对话用的多半不是记忆库这个服务，检查一下对话里选的模型属于哪个服务。

### 使用须知

- 在聊天 App 里删除消息、修改较早的消息，不影响 AI 看到的内容。想重来，只能对最后一轮点重新生成，或改写最后一句再发送。
- 在 App 里切换回旧的回复版本，AI 仍按最后生成的那一版记。
- 记忆库里填了人设时，会替换 App 的系统提示词，App 附带的世界书等内容也不再生效。
- 聊天原话保留 30 天、及时摘要保留 15 天，到期自动清理；已经生成的记忆卡、主题总结和日记不受影响。

## 升级

```bash
cd amber-heart-memory
git pull
./install.sh
```

`install.sh` 检测到已有配置时只做升级：重新构建、自动升级数据库结构、重启服务，配置和数据都保持不变。

记忆数据存在服务器的数据库里，不在 git 仓库里；仓库根目录的 `.env` 不要删，丢了它，已经生成的访问钥匙就都失效了。

## 已知限制

- 每月的主题总结安排在每月 3 号；如果 3 号整天服务器都没开，那个月会跳过。
- 装在个人电脑上的方式没有实测。
- 召回效果还没有公开的评测数字，评测工具和合成数据集在准备中。
