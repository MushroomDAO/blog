# Amber Heart · 记忆管理网页

`memory_core/` 与 `memory_web/` 放在同一个父目录即可独立运行。一个 FastAPI 服务同时提供登录和管理页面：概览、待审核、导入、记忆、聊天与召回、日记、及时摘要、核心记忆、记忆书签、设置（相识日、参与者、访问钥匙、人设、退出登录），不需要 Node 或单独的前端进程。登录后进入概览；一个实例对外服务一位 AI；首次初始化建立一个空间，管理接口与页面不提供创建第二个空间的入口。另一个助手需另部署一套，预算约再多占 600 MB 内存，实际以运行负载为准。底层空间分区与旧安装已有空间仍保留，不自动删改数据。旧地址 `/drafts`、`/cards`、`/participants`、`/topics` 仍可打开，并自动对应到新页面。

## 安装与启动

公开仓库根目录的 `install.sh` 负责安装与升级：生成 `.env`、构建镜像、安装或升级数据库结构并启动服务；`compose.yaml` 可选内置 Caddy 自动 HTTPS，自备反代可参考 `deploy/nginx-subdomain.conf.example`。

需要 Python 3.11+，以及 `memory_core/README.md` 中说明的 PostgreSQL 17、pgvector 0.8.x、迁移所有者和受限应用角色。先按核心说明安装/升级到版本 22，再安装独立网页结构：

```bash
python3 -m pip install -r memory_web/requirements.txt
python3 -m memory_core.storage.install --dimensions 1536
python3 -m memory_web.install
```

安装使用显式导出的 `MEMORY_INSTALL_DSN`。网页迁移独占 `memory_web` schema：版本 1 保存管理员会话与登录限速，版本 2 新增空间访问钥匙密文，版本 3 清除历史作废密文并约束有效钥匙才有密文；schema 注释保存版本、逐版迁移和结构校验，升级保留已有会话，不修改旧迁移文件或核心迁移历史。重复安装核对所有者、结构和授权；出现不一致会停止。只使用核心库/CLI 时不需要安装网页结构或登录。

网页环境变量见 `.env.example`。程序不自动加载任何 `.env`、旧项目配置或数据库 service 文件：

- `MEMORY_DSN`：核心登记的普通应用角色，用于草稿、检索和登录会话。
- `MEMORY_CONFIG_DSN`：核心迁移/配置所有者，仅供服务端初始化空间模板和修改参与者配置。
- `MEMORY_WEB_ORIGIN`：浏览器访问的完整 HTTPS 来源，含非默认端口时也要保留端口；不带路径和末尾斜线。
- `MEMORY_WEB_PASSWORD_FILE`：源码和网页静态目录之外的私有密码哈希文件绝对路径。

网页静态文件（`static/`）在启动时读入内存：所有 `?v=` 引用统一改写为按文件内容算出的版本号，改了文件不用手动改版本号；带当前版本号的文件压缩后发送并允许浏览器缓存一年，页面本身不缓存。网页附带 `manifest.webmanifest` 与图标，可添加到手机主屏幕全屏打开，不使用 Service Worker。

交互式设置密码，再启动服务：

```bash
python3 -m memory_web.admin.password --file /var/lib/memory-admin/password.hash
python3 -m memory_web
```

设置命令不回显密码，只以 0600 权限原子写入 scrypt 哈希；服务运行用户必须能读取文件。忘记密码或需要改密时重复该命令，所有 worker 在下次请求时立即拒绝旧会话，无须重启。

默认监听 `127.0.0.1:8080`，由部署者的 HTTPS 反向代理提供公网入口。代理保留浏览器的 `Host`，例如 Nginx 的 `proxy_set_header Host $http_host;`；网页验证配置来源，不信任客户端伪造的代理 IP。启动命令不加载私人网关路由、定时任务或私人配置；配置嵌入后，启动会先连接该岗位核对维度；聊天、召回和每日任务按各自触发条件调用配置的岗位。本机开发可显式设置 `MEMORY_WEB_LOCAL_HTTP=1`，且来源主机只允许 `localhost`、`127.0.0.1`、`::1`；这不允许公网 HTTP。

## 会话与页面行为

- HTTPS Cookie 为 `__Host-memory-admin`，启用 HttpOnly、Secure、SameSite=Strict；不把密码当浏览器 token。未记住设备时服务器最长保留 12 小时，勾选时 30 天；退出立即删除当前数据库会话。
- 修改请求同时验证来源、JSON 类型、CSRF 和具体业务版本；导入上传使用原文件的二进制类型，保留相同的登录、来源与 CSRF 校验。登录按实例全局限制为五分钟最多十次尝试，多 worker、重启共用计数。会话记录只存摘要、CSRF、密码版本和北京时间 TEXT 时间。
- 空库进入参与者页初始化第一个空间；主题模板默认为恋人，可选通用。已有空间按 AI 配置名字切换。改名保持参与者实体编号、卡片与主题引用；配置按空间修订保存；参与者改名或别名调整与已有卡片的关键词重建保持同一事务，失败一起回滚，不改写记忆正文。新空间的称呼忽略词由模板给定（恋人：宝宝、宝贝、亲爱的、老公、老婆、Daddy；通用为空），网页不填写或修改，保存参与者会保留 CLI 自定义值；参与者表单的“又名（如小名）”用于把同一个人的不同名字关联起来。想让 AI 用某个称呼，可以写在人设或核心记忆。材料保留设置维持已有值。参与者和别名仍用“保存参与者”提交。相识日选定或清除后立即保存，自动入库开关切换后立即保存。人设、核心记忆、书签条目、日记和卡片文字在停输约一秒、失焦或切换页面时自动保存，并显示结果。站内切换会等待保存完成，仍有未保存内容或保存失败时才提示；参与者未提交时维持原有离开提示。保存失败会暂停该项自动保存，直到再次编辑或点“重试”。
- 审核只让用户判断这张卡写得准不准：可改标题、正文和摘要，用下拉框选主题（第一个是主要主题，最多三个，前后端同时校验），勾“里程碑”。经历层、重要程度、情绪、记忆层次、认知状态、内容日期、实体与关系、逐字证据都不显示，保存时按模型结果原样带回；第二步没完成或失败的草稿，用户只需选主题，其余用默认值（稳定、具体经历、无情绪值、无实体关系，内容日期未知时留空，不把业务日期当作事情发生日期）。草稿修改会自动保存，确认收录前会等待最后一次保存成功。保存失败保留当前编辑。仅参与者名字或别名变动用醒目提示列出具体差异；相识日、称呼清单及模板说明更新不显示提醒，确认按钮旁说明将按新设置收录；生成时的设置记录缺失时明确不能还原，不编造变化。版本冲突时在错误旁给出“读取最新版本”；不覆盖未保存的编辑。原文已删除的草稿可拒绝，不能重新编辑或首次收录。 隐藏的人物或事物引用失效、跨空间或有同名歧义时，接口给出可读提示并保留草稿；不擅自删除引用或猜选对象，需要先修复整理结果再收录。
- 收录请求标识暂存当前浏览器会话，断线后按草稿的 `review_key` 核对结果或以原请求重试；重复卡明确提示没有新增。没有进程内收录队列，也不把列表消失当作成功。
- 概览显示相伴天数（填了相识日时；相识当天算第 1 天，未填时显示记忆已收藏的天数）、待审核提醒、记忆总数、本月新增、主题分布和最近收录；点主题分布进入“记忆”并选好该主题，点最近收录进入“记忆”并展开该卡。页面使用“Amber Heart（琥珀之心）”名称，各页均有英文小字、大标题和简短说明；底色为参考图取色的暖米色 `#F6F3EE`，卡片为浅奶白 `#FFFBF8`，主粉为书房粉 `#C1767D`。概览将相伴天数和统计汇总为一张卡，审核提醒右侧提供主色按钮；审核卡头部左侧用 4px 宽的书房粉短线，上下居中并限制在头部内，最长 38px。下拉框为透明底、直角和细下划线，属性与操作区使用卡片本色；摘要用左侧细线区分，不另铺粉色底。手机使用底部图标文字导航，选中项只变书房粉，不铺大色块；待审提醒为小圆点，具体条数保留在概览和审核页，并提供无障碍标签。页头不放退出入口，退出登录仅位于设置页底部（含首次初始化页面）；多空间切换收进设置页，只有一个空间时不显示选择器。记忆页使用细线分隔的紧凑列表，取消每条记忆的外框、底色和阴影；日期与标题并排，当年显示月日，往年保留年份，完整日期通过语义标签和悬停提示保留。展开时左侧用书房粉细线强调，正文保持整行阅读宽度。审核页的操作位于每张卡片最下方，随整页滚动；标题、正文和概括可原位编辑。审核正文阅读时为 13px、概括为 12px，聚焦编辑时变为 16px 并重新适配高度，以避免 iPhone 自动缩放。草稿、最近收录和设置分区以独立卡片显示，配置修订号只在后台用于冲突检测。待审核页将草稿全部展开为竖向列表。收录或拒绝后移走该卡，其余卡片的编辑保留。全部审完显示空态。收录后的卡片去“记忆”查看，被拒绝的草稿从页底链接查看。
- 卡片正文只读；首屏是一排可左右滑动的主题文字标签（全部及有记忆的主题，带数量；选中项以下划线标出），下面是共用一条底线的搜索输入和筛选图标按钮，详细条件默认收起，已选条件以可取消标签显示，回车或改变条件即搜索；日期框有空值提示并限制移动端宽度。主题标签、种类、内容日期筛选与关键词搜索在完整 BM25 命中集上分页，不调用清洗模型、嵌入或精排，不改变自动召回链路。展开卡片显示正文、主题（主要主题在前）和里程碑，提供“修改”和二次确认的“删除”，经历层保留在后台，不显示编号、实体与来源证据。
- 主题只在创建空间时选恋人或通用模板，创建后锁定。设置页没有主题区，也没有主题改名、说明修改或影响查询接口。版本 9 的主题记录用 `preset_key` 指向 `memory_core/presets/topics.json` 的唯一模板项，不存空间说明副本；每次抽取第二步直接读取最新说明并替换参与者名字，更新模板说明后所有空间自动生效。已有主题编号和卡片引用保持稳定。经历层的核心规则、判断和保存保持不变，是否退役留待真实模型对比，见 `OPEN-EXPERIENCE-01`。已审核卡片支持改标题、主题和里程碑以及永久删除；每空间访问钥匙已提供。

底部导航固定“概览、待审核、记忆、召回、设置”五项，待审核用小圆点提示。概览“待办”里的召回异常提醒直达“聊天与召回”（`/conversations`）。记忆页浏览卡片。主题分布下面的四个入口进入日记、及时摘要、核心记忆和记忆书签，这四页保留概览选中状态和返回链接。

## 卡片属性与删除

记忆页展开原子卡片后，可编辑标题、主题（最多三个，第一个为主主题）和里程碑；正文只读，内容有误时可删除错卡。筛选里的“状态”可查看已归档卡，使用同样的编辑与删除操作。主题总结只读，可查看吸收清单并整篇撤销。属性修改、删除、撤销不调用模型。

`PATCH /api/spaces/{space}/cards/{id}` 接受且只接受 `title`、`topic_ids`、`is_milestone`；正文、日期等额外字段返回 422。`DELETE` 同一路径使用空 JSON 对象。两者沿用登录会话、Origin、JSON 和 CSRF 校验，不使用空间访问钥匙。写入失败保留当前编辑，可稍后重试；网络中断时无法确认结果，会保留编辑并提示核对。属性没有卡片版本号，多处编辑以最后一次成功保存为准。

删除前二次确认，后台在同一事务清理卡片、索引、图谱与审核副本，保留抽卡计数；共享实体、参与者及既有主题总结保留。已知限制：没有删除指纹，重复抽卡或重复导入时可能再次出现已删卡。

## 配置接口：相识日

`GET /api/spaces/{space}/configuration` 返回 `acquaintance_date`，未设置为 JSON `null`。相识日为严格的 `YYYY-MM-DD` 有效日期；不接受空字符串、时间戳或自动补零。仅表示日历日期，不做时区换算，也不限制为过去日期。

登录后使用现有 CSRF、来源和 JSON 请求头，以当前 `revision` 修改：

```http
PATCH /api/spaces/example-space/configuration
Content-Type: application/json
X-CSRF-Token: <当前会话的 csrf>
Origin: https://memory.example.org

{"expected_revision": 1, "acquaintance_date": "2024-02-29"}
```

成功返回完整配置及递增后的修订号；将 `acquaintance_date` 设为 `null` 可清空。PATCH 的两个字段均必传；旧修订返回 409，字段/类型错误 422，非法日期 400，空间不存在 404。`PUT /api/spaces/{space}/participants` 也接受此字段，可与参与者一起保存；省略表示保留，显式 `null` 表示清空，兼容旧页面。读写不调用模型，也不自动生成记忆。日期变动保留内部修订校验，不显示草稿设置变化提醒；生成时的设置记录不会被改写。设置页选择相识日或点“清除”时立即调用这个接口。

## 概览接口

`GET /api/spaces/{space}/overview` 只读，不调用模型。返回 `auto_approval`：开关、等待小时数、完整待审数量、下一批每日任务预计时刻和安全失败状态。返回参与者名字、`acquaintance_date`、`days_together`（未设置或日期在未来时为 `null`）、`created_date` 与 `days_collected`、待审核 `pending` 与已拒绝 `rejected` 数、未归档记忆 `cards` 与本月新增 `cards_this_month`（按安装时区的自然月、以收录时间计），以及各主题的未归档记忆数 `topics` 和最近 5 条 `recent`。 `overview_entries` 同次返回最近日记与摘要的日期、核心记忆字数和当前业务日新记且待整理的书签数。缺少日期或旧安装未提供的状态会省略。`GET /api/spaces/{space}/drafts?status=rejected` 只列已拒绝草稿；`pending` 与 `processed` 保持原意。

## 模型边界

召回的嵌入、关键词清洗、文档第一级精排与聊天第二级精排已有 HTTP 实现，配置及降级见 [核心模型配置](../memory_core/README.md#召回岗位配置)。网页默认装配这些岗位，配置嵌入时启动先核对维度；审核收录也使用该嵌入。抽取岗位仍只提供协议和显式固定响应，摘要、日记配置见下文，不会隐式装配假模型。草稿确认在未配置嵌入时明确失败，保留草稿；浏览、关键词搜索、参与者和主题不依赖模型。

仅合成材料验收时显式设置 `MEMORY_WEB_FIXED_MODELS_FILE`，文件格式沿用 `memory_core.testing.fixed_models.FixedModels`；每个输入必须有预先声明的响应。未知输入明确失败，页面标识当前处于固定假响应验收模式。`testing/data.py` 仅生成合成原料和固定响应。固定响应模式不触发真实岗位探测；真实型号选择、成本与质量需在试用时另行验证，抽取接入尚未完成。

### 第一级精排配置

`MEMORY_DOCUMENT_RERANK_FORMAT` 可设为 `voyage` 或 `cohere`。未设置时默认 `voyage`，发送 `top_k` 和带检索指令的查询，读取 `data`。`cohere` 用于硅基流动、Cohere、Jina 等兼容接口，发送 `top_n` 和原始查询，读取 `results`。配置值非法时启动报错；响应缺少所选格式的结果数组时，记录 `document_rerank_format_mismatch` 并沿用粗排顺序。

使用硅基流动时，把下面四项填入部署环境。地址填写基址，程序会拼接 `/rerank`。将示例 key 换成自己的硅基流动 key。 [硅基流动精排接口](https://docs.siliconflow.cn/docs/api/rerank-post)

```dotenv
MEMORY_DOCUMENT_RERANK_FORMAT=cohere
MEMORY_DOCUMENT_RERANK_BASE_URL=https://api.siliconflow.cn/v1
MEMORY_DOCUMENT_RERANK_MODEL=BAAI/bge-reranker-v2-m3
MEMORY_DOCUMENT_RERANK_API_KEY=<SILICONFLOW_API_KEY>
```

## 隔离验收与清理

以下工具只创建带 `memory-web-acceptance` 标签的专属资源。数据库无发布端口，使用内部网络、独立卷、新随机凭据；镜像构建只复制 `memory_core/` 和 `memory_web/`，排除运行状态与本地环境文件，无生产挂载或网络。

```bash
python3 memory_web/dev/environment.py build
python3 memory_web/dev/environment.py start
python3 memory_web/dev/environment.py test
python3 memory_web/dev/environment.py core-test
python3 memory_web/dev/environment.py destroy
```

网页测试覆盖普通默认工厂、登录/改密/退出、期限与并发限速、CSRF、空库初始化、配置/草稿冲突、逐字证据、幂等/重复卡、来源删除、分页/筛选及从受支持旧核心版本升级。每项使用自己的临时数据库。

## MCP 主动查记忆（5A）

同一个服务在 `/mcp` 提供 Streamable HTTP，使用固定的官方 Python SDK `mcp==1.30.0`，无状态运行，不另开端口或子域名。连接时在客户端选择 Streamable HTTP，地址填写 `https://你的域名/mcp`，自定义请求头填写 `Authorization: Bearer <空间访问钥匙>`；钥匙就是设置页里供代理使用的那一把，钥匙决定空间。网址参数、管理员登录 Cookie 和管理员密码都不能代替该请求头。钥匙作废或重生成后，旧钥匙从下一次 MCP 请求起失效；未配置 `MEMORY_ACCESS_KEY_MASTER_KEY` 时接口返回 503。

Kelivo 可按上述方式配置；本批已用官方 Python SDK 客户端完成隔离协议验证，Kelivo 的具体版本及端到端连接效果仍需客户端实测。Claude 官方 App 自定义连接器首发不支持：本接口没有 OAuth，也不开放无验证连接。管理页里的连接说明与复制按钮随 5C 加入。

提供 `memory`（查记忆）和 `mark_moment`（记书签）两个工具，不接收空间编号或任意 SQL。工具描述按空间参与者配置生成。`memory` 只访问已审核卡片，不读待审草稿或聊天原文：

| action | 用途与参数 |
| --- | --- |
| `list_topics` | `source_scope` 必填，列出所选记忆池中实际有卡片的主题。 |
| `browse` | 按主题 `topic`、实体名/别名 `entity`、日期 `date_from/date_to` 及连续文字 `text` 浏览；日期包含当天，默认旧到新。`order=desc` 可倒序。默认每页 30，最多 50。 |
| `search` | `query` 必填，一次查一件事；同样支持主题、实体及日期筛选。三路粗检池最多 60 条，接第一级文档精排，不跑第二级大模型精排；失败或排序不完整时退回粗检顺序。默认每页 10，最多 20。它是相关候选，不是完整清单。 |
| `get` | `memory_id=M-数字` 必填，打开单张完整正文。算一次使用，同时更新 `used_count/last_used_at`；已归档时在同一事务内恢复并更新 `restored_at`，重新开始归档计时。 |
| `get_sources` | 主题总结的 `memory_id` 必填，合并显式来源编号和当前子卡引用，按日期返回仍存在的来源全文。默认每页 20，最多 30。 |

`browse/search` 默认 `source_scope=atomic`，可选 `topic_summary` 或 `all`，默认排除 `outdated`；回顾历史版本时可显式设置 `include_outdated=true`。`browse` 的 `text` 为原文字面查找，不把空格分词，也不把 `%`、`_` 当通配符。翻页使用结果中的 `next_cursor`。`browse/get_sources` 按当前数据分页；`search` 每次重查候选和精排，不保存搜索会话，并发修改或排序变化时翻页结果可能变化。

`search` 直接列出命中的子卡，每张在中文结果及结构化字段 `parent_memory_id` 中标明所属父总结编号，不替换成父总结，也不合并同父子卡。父总结已归档时，子卡仍可被查到；想看总结可以用 `source_scope=topic_summary/all` 搜索，或按父编号 `get`。父总结替换与同父合并只用于代理自动召回。`browse` 保留子卡摘要，`get/get_sources` 可以展开其全文，不解除子卡与主题总结的关系。永久删除的卡片在所有查询中都不可见。`search/browse/get_sources` 均不增加使用次数或恢复归档；MCP 查询不生成代理回执或回执统计，不获取代理空间轮次锁，可在模型发起工具调用后、客户端续轮前执行。

只配置 MCP、聊天不走代理时，聊天不会自动成为卡片，也不能保证日记和每日抽卡拿到对话原文；不提供直接存卡工具。记忆书签见下节。

## 记忆书签与夜间整理（5B）

先用迁移所有者执行 `python3 -m memory_core.storage.install --dimensions <原安装维度>` 升级到版本 20。新增 `recent_notes` 与 `moment_bookmarks` 两张表；不读取或迁移自用版数据。`recent_notes` 保存已整理的书签，`moment_bookmarks` 保存待整理的书签。管理页“记忆书签”提供撤回、四区逐条编辑与秘书整理。

`mark_moment` 挂在同一个 `/mcp`，只认空间 Bearer 钥匙，参数沿用自用版：`action=add/list/update/delete`（不填为 add）；`section=period/health/longterm/daily`，对应月经周期、健康关注、长期事项、日常杂记。add 必须带分区和 content；update 必须带一个 ids 编号和完整的新正文，可指定新分区；delete 可带多个编号。正文换行转换为空格，按原文写入，不由模型补写。记录时间和所属业务日沿用空间的安装时区与分界，改写不改变原记录时间或业务日。

只能操作尚未整理的书签。编号接受 8 位十六进制短编号或完整 UUID，短编号匹配歧义时拒绝；list 返回短编号和 `full_id`，最多 100 条并标出是否还有更多，管理员列表返回全部。查询编号不受 100 条展示上限限制。修改、撤回和夜间整理共享短事务行锁，按实际影响行数判断结果；整理后或撤回时即删除，不留状态副本。已整理的条目无法再通过书签工具修改，有新进展需重新 add。

每日新增独立 `recent_notes` 任务，先于该批日记执行，不依赖日记成功。它收取任务日期之前所有业务日的待整理书签，按记录时间新到旧插在相应分区顶部；漏跑多天会一起补上。四个分区更新、版本号增加一次、删除这一批书签与任务完成在同一事务中提交。只有待整理的书签、没有对话的空间也会参与调度。无新增书签时不改变书签内容版本。

秘书整理只由管理员发起，不在夜里调用模型。`MEMORY_RECENT_NOTES_TIDY_MODEL` 为独立型号；`BASE_URL/API_KEY` 均留空时复用主上游，成对填写时使用专用上游。秘书调用在 OpenRouter、DeepSeek、硅基流动和 OpenAI 上按对应字段启用思考并请求中等强度，实际强度由供应商和型号决定。其他兼容地址沿用供应商默认行为。单次总时限 `MEMORY_RECENT_NOTES_TIDY_TIMEOUT_SECONDS` 默认 300 秒。字数线 `MEMORY_RECENT_NOTES_SOFT_LIMIT=3500`、目标 `MEMORY_RECENT_NOTES_TARGET=3000`，按去掉空白后的字符数计算，目标须为正整数且不超过字数线。

提示词只读取 `memory_core/prompts/snapshot_tidy.md`，逐项 replace `{{…}}`，保留 JSON 示例的花括号。四区分别使用周期/健康/长期/日常前缀。沿用自用版的结果校验：无效、重复目标、重叠、跨分区或不合规则的建议丢弃并说明原因；未超线不接受删除；带★的原文禁止删除，改写后保留★。模型拒绝、截断、无效 JSON 不采用，不自动重试付费调用。

每空间只保存最新一次秘书任务，含状态、基准版本、原条目、建议、待确认问题及型号用量；任务元数据变化不递增书签内容版本。服务重启会将失去执行锁的进行中任务标为失败，不打断其他仍持锁的 worker。取消后的迟到结果不覆盖最新任务。管理页按勾选建议算出四区新正文，长期事项按条目开头的完整起始日期倒序排列（无日期留在原位，同日保持顺序）；采纳时保存并高亮，可在当前页撤销。保存带基准版本与任务编号；基准版本与当前版本不同就返回 409，要求重新整理，任何分区均不写入。夜间整理书签、手改分区和保存采纳结果都按实际内容变化递增版本，防止覆盖新内容。

以下接口沿用管理员 Cookie、Origin、CSRF 与空间检查，空间钥匙不能替代管理员登录。路径前缀为 `/api/spaces/{space}`：

| 方法与路径 | 入参与结果 |
| --- | --- |
| `GET /recent-notes` | 四区正文、version、各分区 counts、total_chars、over_limit、字数配置及最新任务。 |
| `PUT /recent-notes` | `expected_version`、`sections`（一个或多个分区正文）；一次事务保存，空字符串清空。采纳秘书预览时附 `tidy_job_id`，同时标记任务已采纳。 |
| `GET /bookmarks` | 全部尚未整理的书签。 |
| `DELETE /bookmarks/{完整 UUID}` | `{}`；仅撤回仍待整理的书签，已整理或已撤回返回 409。 |
| `POST /recent-notes/tidy/start` | `{}`；后台开始整理，已进行中时返回同一任务。 |
| `GET /recent-notes/tidy` | 岗位是否配置及最新任务。 |
| `POST /recent-notes/tidy/cancel` | `{}`；取消当前进行中任务。 |

已整理的书签在日记之后、及时摘要之前注入；空分区不出现，全空不注入。包裹说明以当前聊天的新信息为准，工具续轮重放首次冻结的版本，后续新一轮才看到夜间更新或手改内容。只用代理时，AI 通过 MCP 接入后才能自动记书签；只接 MCP、不走代理的用户能记书签并在夜里整理，并通过管理接口查看，但聊天里不会注入已整理的书签。

## 托管代理、轮次与访问钥匙（3C）

这一批提供 `/v1/models` 和 `/v1/chat/completions`（文本、当轮图片、流式及非流式），与管理网页共用进程。**聊天只提供后端托管模式：前端旧历史只参与轮次识别，不补录、不转发。** 同空间的前端多个窗口合成一条时间线；前端删除消息、修改更早消息或切换旧回复，不会同步改变后端历史。自动测试只覆盖合成环境，尚未经过真实客户端和供应商验收。

环境变量全部显式配置，真实值不进入源码或 `.env.example`：

| 配置 | 用途 |
| --- | --- |
| `MEMORY_ACCESS_KEY_MASTER_KEY` | Fernet 主密钥，保存在服务器环境及私有备份中，不能与数据库密文同库。仅配置它也能使用钥匙管理。丢失后旧钥匙无法查看或认证，应重新生成空间钥匙；更换主密钥不能直接沿用旧密文。 |
| `MEMORY_UPSTREAM_BASE_URL` | 上游 API 基址，包含 `/v1` 或供应商相应路径。与上游 key 同时配置；不接受地址内的用户名、密码、查询参数或片段。不跟随重定向。 |
| `MEMORY_UPSTREAM_API_KEY` | 仅服务端使用的上游 key；不接受前端覆盖，不转发前端请求头，不出现在错误响应和日志里。 |

生成主密钥可使用 `.env.example` 中的命令。未配置时不影响原有管理网页，钥匙分区说明缺少配置，代理明确返回未配置错误。原有固定假模型只用于后台收录验收；配置真实聊天上游与接入后台模型岗位是不同的事。

登录管理员在设置页生成、重新查看、复制或作废当前空间钥匙。`mk_<非秘密编号>.<随机秘密>` 中的编号定位唯一数据库记录；服务器只解密这一条，恒定时间比较完整钥匙后得到已绑定空间，不接受客户端自选空间。数据库只保存完整钥匙的密文及非秘密元数据。重新生成的作废与新建在同一事务中提交，不缓存认证结果；之后的新请求立即拒绝旧钥匙。已经开始的请求不会因此重新执行。普通应用角色只能读钥匙表，生成/作废使用服务端配置所有者；作废或被新钥匙替换时同时清空旧密文，迁移也会清空历史作废记录的密文。主密钥与有效密文不匹配时返回清楚的 503 服务端配置错误，不回显密文或主密钥。钥匙不能登录管理网页，管理员 Cookie 也不能代替代理 Bearer 鉴权。

管理接口为 `GET/POST/DELETE /api/spaces/{space}/access-key`，写入沿用管理员登录、来源、JSON 和 CSRF 校验。代理请求使用 `Authorization: Bearer <空间钥匙>`，不要求浏览器 Cookie、Origin 或 CSRF。HTTPS 仍由部署入口负责；反向代理须关闭 SSE 缓冲，服务也发送 `X-Accel-Buffering: no`。

自制前端可附加本服务专用的 `memory` 对象，转上游前会剥掉：

```json
{"model":"your-model","messages":[{"role":"user","content":"你好"}],"memory":{"request_id":"frontend-request-1","operation":"new"}}
```

`operation` 可声明 `new/retry/regenerate/edit/non_chat`，可附正整数 `target_turn_id`。明确标记优先；`new` 即使文字相同也新建，`regenerate/edit` 只允许重做最新采用的轮次，`retry` 可重试最新失败/未完成轮次，或明确指定该轮次的失败候选；用户消息须保持原样，重试候选仍在成功后才替换原版。请求编号在空间内唯一：同一编号重复提交返回 409 并附已有请求/轮次编号及状态，不重新调用上游；同编号改内容返回 `request_id_conflict`。需要再次生成时使用新请求编号和明确操作。正常响应头 `X-Memory-Turn-ID`、`X-Memory-Request-ID` 返回编号。

未标明操作时按接续位置的四种情况判断：接在最新回复后是新消息；接在最新轮次原来的同一回复后是重做；没有前置回复时仅纯文字完全相同视为重做；其余视为新消息。例外是最后一轮没有任何 AI 正文：若请求仍接在它原来的回复位置，优先重做这一轮，文字相同为重新生成、不同为改写；若请求历史保留了那条未获回复的用户消息，则是接着说新话，即使新话文字相同也不替换。没有接续位置且只发首句时，仍沿用相同文字的兜底规则。匹配读取已保存的前端可见正文指纹；核心 `finish(..., visible_content=...)` 为 3C 的回执过滤留有明确入口，不以内部未过滤文本作匹配。前端切回旧回复不恢复后端旧版本；被替换版本仅留档，不提供恢复或展示接口。

替换先保存 candidate，不改旧版。只有整轮最后一次生成成功且正文/用量/状态在同一事务中提交后，才把旧版设为 replaced、新版设为 current。工具调用阶段不切换；失败、中断、超时或存档失败都保留旧版。普通新轮次失败时仍保留用户消息；断流保存已收到正文为 incomplete。

`non_chat` 是纯转发：不创建任何对话记录、不注入、不占空间锁，仍须有效空间钥匙。前端辅助请求应关闭、直连供应商或明确标记，不能靠正文猜用途。

### 同空间占用、续轮与超时

同一空间只处理一轮，其他新请求收到 409 `space_busy` 和“此空间正在处理，请稍后再发”；不同空间独立。最后一条是工具结果时优先按续轮处理：只能接续本空间仍在等待的轮次，先按编号匹配尚未完成的整批调用；整批编号不能匹配时，要求前端重发的调用条数、工具名和顺序与待返回批次一致，结果也须完整对应前端的这批调用，再按调用顺序记回账本的原编号。缺少、重复、名称/顺序不符或超时都拒绝，不调用上游。并行结果可按任意完成顺序提交，须一次提供该批的全部结果。续轮归到同一轮的下一步请求，不重复保存用户消息、调用或旧结果。

首次请求先事务保存用户消息，再读取当前采用的历史、调用现有召回并保存本轮的组成清单、召回卡片记录和图片无数据/地址的冻结上下文；历史或召回记录读写失败在调用上游前报错。工具续轮重放冻结前缀；前端中途修改人设或工具定义不会改变本轮。本轮消息照前端重发内容透传，不与账本逐字比较；保留空白正文、reasoning_content 等协议字段及客户端重新生成的调用编号，思考仍不存档。仅提交最新一批结果时，按原调用编号匹配后由账本补全本轮消息。原轮次若有图片，必须由本次前端请求重新携带；用户消息时间仍沿用首次请求。整轮业务日始终取用户消息的时间；最终结束、失败或超时后释放冻结全文。数据库保存的状态与冻结内容可被另一进程接续，不依赖进程内轮次字典。

客户端格式依据（2026-11-11 核对）：[Kelivo 空白正文和思考回传](https://github.com/Chevey339/kelivo/blob/ad141129b61ad03aff60d2ce2c3752e9221cd946/lib/core/services/api/providers/openai/chat_completions_api.dart#L150)、[Operit 重建工具编号](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/api/chat/llmprovider/OpenAIProvider.kt#L1047)、[原生工具桥接](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/api/chat/llmprovider/StructuredToolCallBridge.kt#L279)。

`MEMORY_PROXY_TURN_TIMEOUT_SECONDS` 默认为 300 秒，可配置为正整数。此初始值给联网/浏览器等较慢工具留出等待时间，尚未经过真实客户端耗时验收。正在生成的请求定期续期，工具等待阶段不续期；每次新请求先查超时，后台最多每 30 秒扫描一次，启动时也扫描。超时把轮次标为未完成、清空冻结全文并释放占用；后续迟到任务必须同时匹配轮次、请求编号与随机占用凭证，不能改动新任务。进程被强杀后，旧占用仍由数据库期限释放，不会靠重启强行清掉其他 worker 的有效请求。

已知限制：工具调用中途停止后，这一轮最多还会等待 5 分钟（默认轮次超时）才释放空间，期间发送新消息会提示“此空间正在处理，请稍后再发”。

### 自有工具历史卡片（5D）

下一轮重建历史时，`memory` 和 `mark_moment` 根据已存的调用参数和客户端回传文字留下可读卡片；其他工具仍只留名字和是否返回，不回放其他工具结果。不调模型，不重新查库，不增加 MCP 使用次数或回执。`memory` 留分页、编号/日期/标题/状态及摘要（get 为正文），普通卡最多 500 字、总结 4000 字，search/browse 每次最多 12 条；get_sources 列出这一页全部来源目录，不截 12 条、不附正文，list_topics 留主题列表，明确的查询错误留错误摘要。书签留动作和短结果摘要。日记、及时摘要和抽卡继续只读真实聊天正文，不消费这些卡片。

名称按 2026-11-10 的客户端源码核对：Kelivo 原名无冲突时不变，冲突用 `<服务器名>__<工具名>`，可能加八字符服务器 ID 或数字后缀，整体最多 64 字符；Operit 用 `<服务器名>:<工具名>`，OpenAI 工具调用还可能用 package_proxy/proxy 的 tool_name 与 params 封装。只有名称和返回文字都可识别才生成卡片；截断后认不出名称、未知格式或解析失败时保留原来的一行。当前不推断其他客户端的任意改名规则。

源码依据：[Kelivo 工具路由和文字回传](https://github.com/Chevey339/kelivo/blob/4857da608734ae42058897975c7b2ad573502577/lib/core/services/mcp/mcp_tool_service.dart)、[OpenAI 工具消息](https://github.com/Chevey339/kelivo/blob/4857da608734ae42058897975c7b2ad573502577/lib/core/services/api/providers/openai/openai_tool_transcript.dart)；[Operit MCP 执行器](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/core/tools/mcp/MCPToolExecutor.kt)、[包工具代理](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/api/chat/llmprovider/OpenAIProvider.kt)、[proxy 识别](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/api/chat/llmprovider/StructuredToolCallBridge.kt)。

### 转发与存档

后台聊天模型的每次调用时限按岗位配置：`MEMORY_EXTRACTION_TIMEOUT_SECONDS=600` 分别用于每日抽卡与导入抽卡的每一步，格式错误或超时每步共尝试最多两次；`MEMORY_DIARY_TIMEOUT_SECONDS=300`、`MEMORY_TOPIC_SUMMARY_TIMEOUT_SECONDS=300`，`MEMORY_SUMMARY_TIMEOUT_SECONDS=120` 同时用于一级摘要和二次合并。均为有限正数，单位秒，覆盖连接、模型思考与完整响应体；分段到达不会重置。备用型号的单次调用也使用对应岗位时限，整项任务含重试可能更久。超时沿用失败记录、后台续跑和备用型号规则，不采用半成品。召回各级仍使用原有单次 5 秒、整轮 8 秒的默认上限及剩余总时限，不随后台任务放宽。

调用上游前先事务保存用户消息；失败不调用上游，不重复保存前端旧历史。SSE 保留心跳、跨字节 Unicode、工具参数增量、思考显示和独立用量事件。独立记录任务使用有总量上限的队列，不逐 token 等待 SQL；普通回复不必等存档才发完。工具调用的 DONE 会等该步骤的等待状态保存成功后发出，保证前端的瞬间工具结果可以立刻接续。客户端断开会关闭上游连接并保存已收到正文；不承诺供应商停止计费。

上游连接、HTTP、流式及模型列表错误保留供应商提供的说明，先对配置的上游 key（含 URL/JSON 编码形式）打码，再截短到最多 600 字符加省略号；只返回处理后的说明，不记录供应商原文或凭据。上游失败保留用户输入，不将错误输出当作回复。已经生成的非流式回复即使存档失败也照常返回，和流式一致；存档失败仅记录安全编号、阶段和错误码，并尽力保存 archive_failed 状态。数据库完全不可用时仍无法保证这次错误状态落库，正常停机会收尾记录任务。

请求体上限 16 MiB、单个 SSE 事件 4 MiB、单次回复存档 32 MiB；超限明确失败，一次只接收一份候选回复。及时摘要、整轮长度保护、每日补写日记和保留期清理调度已提供。原话、工具、摘要及原料副本按同一空间策略清理，已写日记保留。测试使用假上游；Kelivo/Operit 真实兼容性、模型质量、费用和生产部署尚未验收。


### 上下文顺序、人设、时间和图片

顺序固定为：人设 → 日记 → 已整理的书签 → 及时摘要 → 当天原话 → 补充上下文（本轮召回 + 当前时间） → 固定 AI 确认 → 当前用户消息。补充上下文是一条 user 消息，固定确认是一条 assistant 消息；人设之后不插入动态 system 消息。召回为空时仍发送当前时间及确认。日记位按安装时区的自然日取近 N 日内已完成的较早业务日日记（默认 N 为 3），最多 N 篇，按日期升序注入，没有日记不发送占位文字；已整理的书签按四个分区注入，全空跳过；及时摘要仅注入本轮业务日有效覆盖的内容。历史按完整轮次读取 current 版本，重做时排除被重做的位置，成功采用后下轮才使用新版本。历史保留用户正文与 AI 各步骤的全部有效正文（含调用工具前的说明），忽略思考、工具参数与结果；工具仅用名称加简短状态说明，按调用顺序保留每个工具名；只区分“已返回”和“未返回”，不根据工具载荷推断成功或失败。没有收到任何 AI 正文时只在用户消息后标“未获回应”；已有正文后中断，或工具前已说过话但整轮失败时，只标“未完成”。

设置中的人设使用与参与者相同的空间配置修订锁，`PATCH /api/spaces/{space}/persona` 接收 `expected_revision` 和 `persona`，陈旧页面返回 409。人设非空就替换前端所有 system/developer 提示词，包括附在其中的世界书；空白保存为空字符串，沿用前端提示词。修改从下一轮开始，已开始的工具轮次继续用冻结人设。人设最多 100000 字。设置页可导入 UTF-8 编码的 .txt、.md，以及 .docx。Word 文件在浏览器里提取正文段落为纯文本，解压后的正文 XML 最多 32 MiB。现有人设有内容时会先确认替换，导入后与手动编辑一样自动保存。

原话存储不带时间前缀，发给上游时给用户消息加 `[月-日 时:分]`；当前时间与召回合成一条补充上下文，显示“年-月-日 周几 时:分（时区）”，不带秒和偏移；紧随固定确认，再放当前用户消息。全部时间和业务日来自核心安装配置，工具续轮沿用本轮首次时间。当天首次发言时，默认借前一业务日末尾至少 4 条正文，按完整轮次取，不切开工具轮次；之后当天连续发言继续重放这段前缀，直到当天第一份摘要成功生成，避免第二句撤掉它。`MEMORY_PROXY_PREVIOUS_DAY_MESSAGES` 可设 0–1000，0 关闭借用。之后的图片有后台描述时显示“[图片：描述]”，未完成、未配置或失败时仍显示“曾发送图片，图片内容未保留”，当前图片原样传递，冻结只存位置，续轮必须从前端再次携带图片。

模型能看到的固定文字统一在 `memory_core/conversations/chat_text.py`。上游 JSON 统一排序对象键，避免数据库 JSONB 重排造成首次与续轮字节不同；消息数组顺序不变。测试比较连续轮次未变前缀、工具续轮（含图片）的字节，未添加供应商缓存标记，也不承诺命中率。

### 召回、总时限和回执

本轮用户纯文字送入现有 `RecallService`，图片不参与查询，纯图片直接跳过。关键词整理失败使用去掉称呼的原句。文档精排失败用粗排顺序，最终精排失败取这一顺序的前五条。到达 `MEMORY_PROXY_RECALL_TIMEOUT_SECONDS`（默认 8 秒）时使用已完成阶段的最好结果，粗排尚未完成时跳过注入。主题总结的正文后带 M-编号和 `memory` 工具的 `get_sources` 调用提示。结果、状态、降级阶段、实际注入的编号/卡片全文和上下文组成保存在本轮，不作为新的聊天原料。工具续轮直接使用冻结内容，不重新召回、读新人设或刷新卡片。

总时限包括召回服务初始化、清洗、检索、两级精排与召回卡片记录读取。同步调用到点时可能还在后台结束，轮次沿用到点前已取得的卡片，并停止后续阶段。正常启动装配 HTTP 岗位，未配置岗位按既有逐级退路运行并记录降级或失败。合成验收显式使用 `MEMORY_WEB_FIXED_MODELS_FILE` 或 Python 工厂的 `recall_models` 注入。

注入说明从空间配置取用户名字，明确记忆是过去的时间切片，不能套用旧结论代替对当下消息的回应。模型回复末尾的 `<used>1,3</used>` 只报告本轮本地编号，`<used>无</used>` 则明确报告未使用。流式与非流式共用增量过滤器，处理跨字符/字节片段、重复及不完整标记；标记不发前端、不入聊天正文，不从中提取新原料。格式不完整或不是末尾报告的不计数，只接受本轮实际注入的编号。记录的正文与接续匹配均为过滤后的版本。

回执和正文在同一事务里提交；同一时间线位置的工具多步、失败重试、重新生成即使再次报告同卡，也只增加一次 `used_count`，记录 `last_used_at`，不修改卡片语义更新时间。前端重发相同请求编号仍返回原有 409，不再调用模型或计数。页面区分“模型报告使用 / 模型报告未使用 / 未报告”；未报告不代表没用过。完整的“无”保存为 `reported_unused`，不增加次数；重复“无”不重复计数，截断或矛盾的“无”不记为未使用；有效编号仍只以本轮实际注入的卡片为准。

### 只读对话页

“召回”页使用 `GET /api/spaces/{space}/conversations` 分页读取当前采用的轮次，按日期分段显示用户和 AI 气泡，工具调用按本轮顺序显示简短摘要。工具行只提供名称、可识别的记忆查询及结果状态。带召回的 AI 回复下可展开本轮冻结的卡片和这一步的回执；有摘要时还可展开本轮实际采用的摘要。概览的“及时摘要”页分页查看每份一级/二次摘要、合并状态及其覆盖轮次，覆盖列表给出原话时间和用户正文节选；原文已删或版本变化会明确标注。用户无回复、失败、未完成与等待工具均有状态；过期原文显示已删除。`GET /api/spaces/{space}/conversations/{turn}/recall` 同样限制空间和 current 版本，不返回密钥或冻结全文。正文和卡片按文本转义显示，对话页没有写入、删除接口。概览统计所有保留轮次的召回超时、失败和降级次数；过期后召回记录清空，不作为永久诊断日志。


### 及时摘要、三合一与长度保护（3D）

`memory_core` 版本 12 增加 `conversation_summaries` 和 `conversation_summary_turns`。前者保存一级/二次摘要、型号/用量、来源历史修订和合并关系；后者精确绑定一级摘要覆盖的轮次版本，外键同时限制空间及业务日，唯一键防止重复覆盖。生成时不占用聊天轮次锁；返回后才在短事务中重查当前版本、正文摘要指纹和接力边界，同时提交摘要及全部覆盖关系。覆盖版本变化的结果不采用；普通追加消息不使有效来源失效。读取时再核对采用状态和保留状态，异常覆盖退回原话，合并异常时保留有效一级摘要。正常重新生成只改最新轮次，接力不被摘要；额外的已覆盖保护会拒绝替换已覆盖版本。

计数按轮：每轮固定算 2 条，无回复/中断轮次也按这一口径计，工具前的多段 AI 正文不增加条数，等待工具或仍在生成的轮次不消费。默认未摘要满 28 条（14 轮），最旧 12 轮生成一份摘要，末尾 2 轮接力。任务迟到时每次仍消费一个固定周期，多出的轮次留到下一周期；超过原话字符预算会提前按整轮摘要，仍保留配置的接力轮次。每个业务日未合并一级摘要达到 8 份，最旧 3 份合成一份二次摘要；一级正文保留，只有成功提交二次摘要后才切换注入，二次摘要不再压缩。当前业务日全部有效二次摘要和未合并一级摘要按来源顺序注入，不限制为最近 8 份。

原料只取用户正文、这一轮全部有效 AI 正文、图片描述（未完成时为占位）及未获回应/未完成标注，不读取工具载荷、思考和使用回执。一级摘要按时间顺序保留生活细节，限 450 字，附上本业务日最近三份一级摘要作为避免重复的前情。一级、二次提示词及注入/省略说明唯一来源为 `memory_core/conversations/chat_text.py`，名字取空间参与者设置，注入块头标明业务日的起止时刻。摘要以稳定 system 段放在人设、日记位之后、原话之前；两次摘要提交之间该段逐字节重放，工具续轮始终保留首次冻结的摘要和原话。模型调用开始后跨业务日，结果只可能归原业务日，不进入新业务日的注入。

后台在轮次终止并存档后调度，不等待摘要才给前端回复；同进程合并重复触发，跨进程使用每空间的数据库会话锁，模型调用时无打开的数据库事务。锁忙时后台等待并重查，避免另一个 worker 正好收尾时丢掉新触发。生成/保存失败只记安全阶段、类型及错误码，不标记覆盖、不丢原话，下一轮结束再试。进程中断后数据库自动释放会话锁，下一轮可重新检查；本批没有独立任务队列或后台定时巡检。

| `MEMORY_SUMMARY_MAX_HISTORY_CHARS` | 30000；异常长原话的 Unicode 字符兜底预算，包括跨日接力，不含图片数据。 |
| `MEMORY_SUMMARY_MODEL` | 显式指定摘要型号，无硬编码默认型号。未配置时保留原话并记录配置错误，不装配假模型。 |
| `MEMORY_SUMMARY_BACKUP_MODEL` | 可选备用型号；每个型号最多尝试两次，主型号两次均失败后切换备用。 |
| `MEMORY_SUMMARY_BASE_URL` / `MEMORY_SUMMARY_API_KEY` | 默认同时复用主聊天上游；专用地址和钥匙须成对配置，钥匙不进日志。 |

摘要调用使用配置上游的 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，只有完整 `stop` 正文才采用；空回复、截断、HTTP/网络错误按失败处理，按上表顺序重试。每次调用使用摘要岗位时限，不跟随重定向，不加载私人配置；真实摘要质量与供应商兼容性仍需真实接入验收。

30,000 字符是异常长原话的兜底预算，正常聊天仍由 28 条触发摘要；它不是 token 数，也不是整个模型上下文的上限。摘要失败或后台尚未完成时，若原话仍超预算，本轮只带预算内的最近完整轮次，并在补充上下文中明确说明省略了多少轮，涉及细节时请 AI 向空间设置中的用户确认；当前用户消息保持完整。单轮原话本身超预算时整轮省略，不截半句话。被省略轮次仍在数据库，`context_manifest.history_omitted` 保存其编号和数量，对话页显示同一事实；摘要结果、人设、召回和当前消息不在这个原话预算内，实际型号窗口需要另行核对。

摘要与原话沿用同一空间保留策略（默认 30 天、可永久）。`ConversationStore.expire` 从覆盖原话的时间判断，清空到期一级及关联二次摘要正文，保留编号、合并与覆盖墓碑；工具、原话及其原料副本仍按原有事务一起清理。每日清理通过下方的任务表调度。只读管理接口为 `GET /api/spaces/{space}/summaries` 和 `GET /api/spaces/{space}/summaries/{id}`，普通空间钥匙不能进入管理接口。


### 日记与每日任务（3E）

核心版本 13 的两张表是 `conversation_diaries` 和 `daily_tasks`。日记每空间、每个日期最多一篇，保存正文、来源轮次版本/指纹、型号用量及编辑修订；任务用空间、种类、日期作唯一键，保存运行、完成、跳过、失败状态和重试信息。普通应用角色没有删除表或记录的权限。

服务内每 30 秒检查一次应执行任务；时区和业务日分界读取安装配置。默认在分界后 15 分钟为前一日写日记，`MEMORY_DAILY_RUN_TIME` 可指定同一时区下的 HH:MM，必须晚于分界时刻。启动时检查漏日，最多补写最近 30 天，可配置。无对话的日期跳过；仍有工具等待/生成的日期稍后重试。只使用该日当前采用版本的全部正文和图片描述（未完成时为占位）、未获回应/未完成标注，不使用工具档案、思考或回执；正文组装与摘要复用同一处实现。日期中若已有原话到期或被清理，就跳过，避免用残缺原料冒充完整日记。

每空间每日工作批次用数据库会话锁互斥，模型调用时不打开事务，也不占聊天锁。任务的执行次数约束迟到 worker 的提交权；日记与任务完成状态在同一事务中落库，来源版本、正文或设置变化时结果不采用。失败保留原话，五分钟后重试。已成功提交的任务不重复执行，已有日记不自动重写。若进程恰在模型已返回而尚未提交时退出，恢复后可能重新调用模型，但不会重复发布或覆盖日记。

每个每日批次先独立处理已结束业务日的待整理书签，再按日期补写日记和抽卡，最后执行到期清理；书签整理和抽卡都不依赖日记成功。清理复用 `ConversationStore.expire` 的同批事务：默认 30 天（可永久）的原话、工具载荷、摘要、召回记录和交给原料表的副本一起清空，保留编号与来源墓碑。日记和已生成的卡片不因原话到期删除。清理任务幂等，重启后重复检查不会恢复被清理内容。任务种类由服务端处理器登记；每日抽卡复用同一任务表、数据库锁、执行权检查与重试机制。

日记放在人设后、已整理的书签和及时摘要前，日期窗滚动、新日记发布或人工编辑时更新。工具续轮继续使用首次冻结的版本，组成清单保存实际日记编号和修订。生成提示词、材料说明和注入说明统一在 `memory_core/conversations/chat_text.py`，名字来自空间设置，生成材料带已保存的人设和核心记忆。

| 环境配置 | 默认与含义 |
| --- | --- |
| `MEMORY_DIARY_MODEL` | 必须显式指定；未配置时保留原话并记录安全配置错误，不装配假模型。 |
| `MEMORY_DIARY_BACKUP_MODEL` | 可选，主型号失败后尝试一次。 |
| `MEMORY_DIARY_BASE_URL` / `MEMORY_DIARY_API_KEY` | 默认同时复用主上游，也可成对指定专用地址/钥匙；钥匙不进日志。 |
| `MEMORY_DIARY_RECENT_COUNT` | 3；同时控制自然日回看范围和最多篇数，0 关闭注入。 |
| `MEMORY_DIARY_BACKFILL_DAYS` | 30；补写天数的上限，同时受原话保留期约束。 |
| `MEMORY_DAILY_RUN_TIME` | 留空为配置分界小时后的第 15 分钟；或填写严格晚于分界的 HH:MM。 |

日记与摘要共享公开 Chat Completions 传输，型号、凭据与错误码按岗位分开，不改变主聊天上游。完整 stop 正文须至少 100 字，含拒绝话术或过短时尝试备用。输入包含全日正文，本批不做静默裁剪，真实型号窗口和质量仍需接入验证。

记忆页有“记忆卡片 / 日记”分栏。日记支持分页、展开阅读和编辑，采用细线列表与同排日期。保存使用日记自己的修订号，过时编辑返回 409 并保留输入；离开页面、切换分栏/空间会保护未保存内容。用户修改后标记“已修改”，不受原话到期影响。接口为 `GET /api/spaces/{space}/diaries`、`GET/PATCH /api/spaces/{space}/diaries/{id}`；编辑沿用管理员登录、来源、JSON、CSRF 和空间校验。


### 每日抽卡与审核方式（4A）

`MEMORY_EXTRACTION_MODEL` 必须显式填写，没有默认或隐藏备用型号；未配置完整岗位时跳过抽卡，不把日期永久记成“已跳过”，概览显示“未配置”，配置后可补抽保留期内日期。`MEMORY_EXTRACTION_BASE_URL` / `MEMORY_EXTRACTION_API_KEY` 同时留空时复用主上游，也可成对设置。两步使用同一显式型号、现有筛选/结构提示词和解析约定，经公开 Chat Completions 传输调用；失败不改用其他型号。固定假响应仅在明确配置测试文件时启用。

服务每天在日记尝试之后处理前一日期的当前采用正文。`MEMORY_EXTRACTION_BACKFILL_DAYS` 默认 30，可配 1–30，同时受原话保留期约束；安装时区、业务日和 `MEMORY_DAILY_RUN_TIME` 与日记共用。空日和已到期材料跳过，生成中或工具等待的轮次稍后重试。失败五分钟后重试，已成功步骤、草稿与审核结果复用；两步未全部成功时不自动通过任何新草稿，不写不完整的正式卡。完整卡片可逐张提交，后续卡失败不撤销已经完整入库的卡。

设置页只提供“未审核的卡片 48 小时后自动入库”开关，默认开启，关闭即为纯人工审核。等待小时数可通过 `MEMORY_AUTO_APPROVE_AFTER_HOURS` 配置，页面同步显示实际小时数。`PATCH /api/spaces/{space}/auto-approval` 接受 `expected_revision` 与布尔值 `auto_approve_enabled`，沿用管理员登录、Origin、CSRF 和配置修订校验；旧修订返回 409，普通空间钥匙不能操作。旧 review-mode 接口停用。

所有新卡片先完整进入待审核，满等待时长后由之后那次每日任务调用和人工相同的审核事务。人工保存修改会重新计时，重试和开关变化不重计。概览显示待审核数量，以及第一批满足时长后的每日任务预计时间；关闭时说明仅手动收录，任务失败时说明保留待审并重试。原已选逐张审核的空间升级后保持关闭，原自动通过保持开启；既有待审从升级时重新计时。

抽卡后改过影响抽卡的设置（参与者、核心记忆等），或当天原对话被改写，到期草稿无法自动复核：每日任务把它标为“需要手动确认”（`error_code=manual_review_required`）并照常完成，不反复重试；概览单独计数，待审核页说明原因。人工保存会按新设置重新核对并清除标记。审核页确认收录前，只要草稿的设置修订落后就先保存再收录，不只限名字变化。

到期收录独立挂入每日任务，即使没有配置抽卡型号，也可处理已有到期待审。计划时刻仍由 `MEMORY_DAILY_RUN_TIME` 和安装时区决定；补跑/重试不能提前处理原计划时刻尚未满等待时间的草稿。主题总结复用同一开关、48 小时起算和每日任务。

概览显示岗位配置状态、最近一次整理的新增/待审数量和查看记忆入口。每个日期的 `daily_tasks.model_usage` 累计两步与重试的阶段、型号、执行次数、时间及数值用量，不保存提示词、正文、供应商错误文字或 key；失败和重试不清空之前用量。模型未返回用量时记为未知，截断但返回用量的响应也计入。服务在请求已发出、尚未记录返回信息时中断，无法补算未得到的供应商用量，应以账单为准。


## 归档与恢复（4C）

每日顺序为日记、抽卡、回执补判、月度主题总结（每月 3 日）、到期自动入库、归档、保留期清理。

回执补判是可选岗位（`MEMORY_RECEIPT_JUDGE_MODEL`，地址和 key 默认复用主上游，关闭思考）。它为前一业务日挑出“注入了卡片、但最终请求回执仍为未报告”的当前轮次，把卡片和 AI 最终正文打包，一晚通常一两次调用，由小模型判断每轮用了哪几张卡。结果按模型回执的同一规则计数：同一时间线位置只计一次，`last_used_at` 取该轮完成时间且不会往回改；状态记为 `judged` / `judged_unused`，页面显示“夜间补判使用 / 夜间补判未使用”，并计入归档回执率。只认该轮实际注入的编号（接受数字字符串）；模型漏掉的轮次，或只给出无效编号的轮次，保持未报告，与实时回执一致。写入时每轮单独提交，并先取得与实时存档相同的空间对话锁，再核对该轮仍是当前版本、未删除且仍未报告，所以与同位置的重新生成交错时也只计一次。输出格式错误会重试一次，仍失败则任务记失败、下次重试，已写入的批次不会重复计数。已知限制：分批中途失败后重试，任务结果里的轮数只统计重试那次处理的轮次，卡片计数本身不受影响。补判的是“回复是否基于卡片说话”，同一件事也可能出自当天原话，偶有误判；归档要隔数月未用才动手，影响有限。未配置时不建任务。

归档复用每日任务的同空间锁、日期幂等键与失败重试，不依赖抽卡型号是否配置；只有导入卡片、没有对话的空间也会检查，样本不足时跳过。归档与恢复均不调用模型。期限、回执统计口径和已知限制见[核心归档规则](../memory_core/README.md#在场卡片归档与恢复版本-17)。

概览接口增加 `archive_health`：近段时间注入/报告的轮次数、回执率、门槛、是否暂停及原因。概览在样本不足或回执率低时明确显示暂停并保留卡片。记忆页打开筛选，选择“状态 → 已归档”，即可按归档月份查看；内容日期筛选仍按卡片原有日期，归档月份另算。归档卡片详情的“恢复”会从恢复时重新计时，原使用记录不改；原有修改属性和永久删除继续可用。

`GET /api/spaces/{space}/archive-months` 返回当前归档月份及数量；`GET .../cards?archive=archived&archive_month=YYYY-MM` 复用原搜索、主题筛选和分页。列表及详情带 `archived_at`，`POST .../cards/{id}/restore` 接受 `expected_archived_at`，沿用管理员登录、Origin、CSRF 和空间检查；归档已变化返回 409，重复恢复不重计。返回成功后列表重新查询，当前月最后一张恢复后可看到空列表。


## 主题总结与审核（4D）

显式设置 `MEMORY_TOPIC_SUMMARY_MODEL` 才生成主题总结；未填时跳过，概览显示“未配置”。`MEMORY_TOPIC_SUMMARY_BASE_URL / API_KEY` 同时留空时复用主上游，同时填写时使用岗位专用地址和钥匙。不自动选择主聊天型号；审核生效仍使用同一嵌入岗位。窗口张数配置和核心规则见[主题总结](../memory_core/README.md#主题总结版本-18)，提示词集中在 `memory_core/lifecycle/topic_summary_text.py`，名字来自空间设置，正文限 80–350 字。调用使用 `temperature=0` 和 `max_tokens=12000`；单个窗口失败会记录，其他窗口继续生成。

每日计划使用安装时区和 `MEMORY_DAILY_RUN_TIME`。每月 3 日创建当月任务，按已结束月份积累；同空间不并发执行，批次与每日任务记录防重复。失败窗口保留失败记录和用量，未处理的来源留待下次月度整理。若当月任务本身失败或中断，可以在 3 日之后续跑。已知限制：服务整个 3 日都未运行且没有建立当月任务时，新的整理要等下月 3 日；卡片保留，不补造过去的运行记录。超过窗口上限时先报错，不调用模型，不截断来源。

待审核队列合并卡片和主题总结，保留四项导航。总结显示正文、将吸收的卡片以及跳过仍保留的卡片，只提供确认或驳回；不编辑正文、不逐张切换。概览的待审数和预计自动入库时刻包含总结。生效后从记忆页筛选“主题总结”，可展开查看吸收清单并整篇撤销；撤销前二次确认。已归档总结也能恢复或整篇撤销。

接口沿用管理员会话、空间检查、Origin 与 CSRF：

- `GET /api/spaces/{space}/topic-summaries/{id}`：只读批次及当前仍存在的来源卡片。
- `POST .../{id}/approve`：`expected_version / expected_policy_revision / request_key`，重复成功复用同一总结卡。
- `POST .../{id}/reject`、`POST .../{id}/revoke`：`expected_version`；驳回或撤销后，下次延伸窗口重写。
- 不提供总结的编辑接口。记忆卡详情中的 `topic_summary` 为有批次的总结提供编号与版本，原子卡与主题总结编号在审核队列用 `item_kind` 区分。

生效前会重新核对来源卡片和参与者。素材已改或删除时保留旧待审总结，并提示驳回后重新整理，不悄悄按旧正文吸收新卡。


## 图片描述（3F）

设置 `MEMORY_IMAGE_DESCRIPTION_MODEL` 启用能看图的聊天兼容岗位；不选择默认型号，没配置时保持原占位。`MEMORY_IMAGE_DESCRIPTION_BASE_URL / API_KEY` 成对配置，均留空则复用主上游。`MEMORY_IMAGE_DESCRIPTION_BACKUP_MODEL` 可选，仅在 `content_filter`、结构化拒绝或明确的内容拦截错误码时换用（兼容 [OpenRouter 官方错误结构](https://openrouter.ai/docs/api_reference/errors-and-debugging)的 `error.metadata.error_type` 和旧版 403 + `reasons`；不保存其中的原始输入）；连接、鉴权、限流、截断和普通接口错误不切型号，也不重复尝试。没有协议标记、只用普通文字表达的拒绝无法可靠识别，不靠猜词触发备用。

只处理普通聊天中本轮用户发来的图片。非聊天请求、前端旧历史、工具结果及工具续轮不重复描述。图片按 [Chat Completions 官方接口定义](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)的 `image_url` 入参传给配置的模型，不在服务器下载或落盘；描述请求使用 `max_tokens=800`，型号须支持该兼容格式。当轮原图仍完整交给主模型，即使主模型不支持图片，也不使用描述替换它。

对话记录及摘要覆盖原话预览复用后端同一处文字渲染，有描述时显示 `[图片：描述]`，尚未完成或失败仍显示占位；原始匹配内容不改。

描述后台独立运行，流式与非流式回复均不等待；一次请求的多张图片按顺序汇总后只写一次。每个服务进程默认最多并发 2 个描述调用、保留 4 条待完成的带图消息，每条最多后台描述 32 张图片；超出时仅跳过描述、保留占位，当轮转发不变。分别由 `MEMORY_IMAGE_DESCRIPTION_CONCURRENCY / MAX_PENDING / MAX_IMAGES` 配置；多进程部署时，各进程分别计数。`MEMORY_IMAGE_DESCRIPTION_TIMEOUT_SECONDS=30` 是每个型号单次调用的总时限，含读取完整响应；只允许一次明确拦截后的备用调用。

已知限制：不保存原图和地址，所以服务重启未完成、失败、超出容量或未配置时跳过的旧图片不会补描述；需要重新发送才有原图可处理。已生成的摘要、日记或卡片不会追改。所有调用用量保存在消息结果中，失败日志只记空间、消息/轮次、图片序号和安全错误码。测试库使用合成 PNG 与假服务，不需要任何真实模型钥匙。

## 核心记忆与书签编辑（5C）

从概览进入“核心记忆”或“记忆书签”。核心记忆写关于用户的长期事实和双方约定，人设写 AI 自己。核心记忆只由管理员手写，最多 5000 字（包含空白和换行，按 Unicode 字符计数），显示字数；凭据等敏感内容仍会拒绝。`PATCH /api/spaces/{space}/core-memory` 接受 `expected_revision`、`core_memory`，返回最新配置；冲突返回 409，保留页面编辑供核对。保存从下一轮生效，注入顺序为人设、核心记忆、日记、已整理的书签、及时摘要；空正文不注入。

“今天新记的”显示待整理的书签；“已整理的”按行显示四区，每条可修改、删除、标★，每区可手动加一条；文字停输约一秒、失焦或离开前自动保存，删除和标★立即保存。秘书整理按分区展示原文、新文、字数变化、待确认问题和未改动条目。勾选后可采纳所选建议，采纳即保存，并可在当前页撤销。采纳前和保存时都核对基准版本，已变化就提示重新整理。开始或采纳整理前会先完成待存的手改。待整理的书签可查看、撤回。

## MCP 客户端连接

设置页自动用 `MEMORY_WEB_ORIGIN` 生成 `/mcp` 地址，并提供地址、传输方式、请求头名称和值的复制按钮。使用 Streamable HTTP，唯一鉴权为 `Authorization: Bearer <访问钥匙>`；与设置页“访问钥匙”的代理钥匙是同一把。复制请求头值会包含 `Bearer ` 前缀；钥匙轮换后客户端需同步替换。不要把钥匙放在地址中。

Kelivo：设置 → MCP →“添加 MCP”，“名称”可填“amber-heart”，“传输类型”选 **HTTP**（即 Streamable HTTP），“服务器地址”填完整 `/mcp` 地址；“自定义请求头” → “添加请求头”，将“请求头名称”设为 `Authorization`，“请求头值”设为 `Bearer <访问钥匙>`，保存并启用。

Operit：MCP 配置页 →“导入”→“远程”，“主机地址”填完整 `/mcp` 地址，“连接类型”选 **httpStream**。在“自定义请求头”→“添加请求头”中填写 `Authorization` 和 `Bearer <访问钥匙>`；“Bearer Token（可选）”留空，完成连接。也可在“配置导入”的“配置内容”中粘贴：

```json
{
  "mcpServers": {
    "amber-heart": {
      "type": "streamable_http",
      "url": "https://你的域名/mcp",
      "headers": {"Authorization": "Bearer 你的访问钥匙"}
    }
  }
}
```

上述名称与传输值于 2026-11-10 对照客户端源码确认：[Kelivo 编辑界面](https://github.com/Chevey339/kelivo/blob/4857da608734ae42058897975c7b2ad573502577/lib/features/mcp/widgets/mcp_server_edit_sheet.dart)、[中文名称](https://github.com/Chevey339/kelivo/blob/4857da608734ae42058897975c7b2ad573502577/lib/l10n/app_zh.arb)；[Operit MCP 配置页](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/ui/features/packages/screens/MCPConfigScreen.kt)、[中文名称](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/res/values/strings.xml)、[配置导入解析](https://github.com/AAswordman/Operit/blob/16cffb98f52a11dc77bd0a789ffa0b01ed398ee4/app/src/main/java/com/ai/assistance/operit/data/mcp/McpConfigImportParser.kt)。

只用代理、聊天前端没配 MCP 时，AI 不会自动记书签，用户仍可手动编辑已整理的书签。只接 MCP、不走代理时能记书签、管理页能看，但聊天里不会自动注入已整理的书签和核心记忆。


## 导入（第 6 块）

设置页“导入记忆”分区进入 `/imports` 二级页，不占底部导航。只上传 conversations.json、conversations-000.json 等分片或 MyActivity.json，不要上传带图片和附件的整个官方导出包。JSON 超过 90 MiB 时，只把聊天 JSON 单独压成 ZIP 后上传；多个分片可一起压缩。Claude 支持 `chat_messages/messages` 与 `sender/role`。Gemini 在 Takeout 的 My Activity → Gemini Apps 选择 JSON，按安装配置切分后的业务日期范围选择，范围内的普通聊天和 Gem 聊天都导入，不提供 Gem 筛选；其他两家默认选中全部对话，可取消不需要的对话。记忆文件示例：

```markdown
## 2025-03-14
每周学习一次陶艺，这是我给自己定下的约定。

## 2025-03-15
第一次做好了一个杯子。
```

上传与预览不调用模型。预览排除已导过的材料，列出对话标题、日期、天数、消息数/记忆条数与模型调用范围。聊天为每份对话日期的一次筛选，加该日共享剩余额度内的整理，具体张数需筛选后才知道。记忆每条一次整理。格式、超时或限流重试使每步调用最多两次，不估算金额。确认后用已配置的 `MEMORY_EXTRACTION_*` 岗位处理，未配置时仍可预览、确认明确报错。卡片显示已处理、失败、跳过数量与实际调用次数，近期记录显示最近 20 批。 确认页默认勾选“整理好后直接收录，不进待审核”。任务保存这次选择。直接收录沿用正常审核的入库事务，整理或收录失败的草稿由人工处理。取消勾选则沿用原有待审核和到期收录设置。直接收录需要核心版本 23，升级前已确认的任务保持原来的选择。

`MEMORY_IMPORT_CONCURRENCY=3` 控制整个服务同时处理多少份导入材料，最小为 1。数据库会话锁负责选出执行进程，事务内领取的条目由单个执行线程处理。遇到服务商 429 时共享退避时间，暂停 2–60 秒后错开请求。这段等待和模型调用都在数据库事务外，每日抽卡不占导入执行名额。

核心版本 24 起，运行中的进度卡在本次第一条材料处理完后显示预计剩余时间。每次刷新按本次已用时间除以本次已处理条数，再乘剩余条数计算。计时从确认、继续或重试起算，预览及暂停期间不计入。升级前已经开始的任务没有可靠的计时起点，下次继续或重试时才开始估算。

单项失败后继续处理其余材料，任务最终显示失败条数，点“重试失败的 N 条”仅重跑失败项。设置改变或材料过期会暂停整批。点“停止”后不再领取新条目，已领取的条目仍会完成当次处理并保存草稿。点“继续”恢复等待与失败的条目。服务正常停机时，也会等待在途条目结束。重启后恢复已领取但还没结算的条目，已保存的筛选与整理结果直接复用。外部模型已收到请求、结果尚未落库时遇到进程中断，该次调用可能重发。

待审草稿按竖向列表展开，编辑、拒绝和收录针对单卡。整理失败会显示原因，也可只重跑该卡的结构整理。记忆文件的正文按共享成文规则决定是否改写，留存的原文可以在卡片详情展开。导入不会补写日记，也不提供整批撤回。已结束的月份按内容日期进入现有园丁窗口。导入原文不会进入聊天历史、摘要或日记，已审核卡片仍正常参与记忆召回。防重和原材料保留规则见[核心导入](../memory_core/README.md#导入版本-22)。

管理员接口：`GET /api/spaces/{space}/imports` 查看配置与进度，`POST .../imports/upload?source=chatgpt|claude|gemini|memory&filename=...` 以 `application/octet-stream` 上传一个原文件，`GET .../imports/{id}` 查看任务，`POST .../{id}/preview` / `confirm` 接收 `selected_conversations` 或 `date_start/date_end`，`confirm` 可另传布尔值 `auto_approve`，`POST .../{id}/retry` 和 `POST .../{id}/stop` 接收空对象。其余操作保持 JSON；全部使用管理员 Cookie、Origin 和 CSRF，不接受空间访问钥匙。上传文件上限为 90 MiB，ZIP 内相关 JSON 解压后累计上限为 1 GiB；nginx 样例同步限制为 90m。JSON 使用流式解析并分批入队，ZIP 成员通过 open 读取，不整体展开进内存。预览和确认只读元数据。上传和 Gemini 按日排序的临时文件放在密码文件所在的私有状态目录（默认是磁盘 app_state 卷），该目录须可写；完成或出错后清除临时文件。不要把此目录改为 tmpfs，否则磁盘暂存仍会占用容器内存。
