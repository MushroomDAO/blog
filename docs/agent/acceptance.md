# 语义检索 / 智能推荐功能 验收标准（用户视角）

> 判断依据只有一条：这些事情能不能真的替我做掉，且我敢让它替我做。
> 记录日期：2026-08-20

## 一、我在博客上输入一段诉求，能找到相关文章

读者/粉丝在博客的搜索入口输入一段自然语言（可以是关键词，也可以是一整句诉求），
系统返回若干篇相关文章，每篇能看到命中的标题、章节或片段，帮助读者判断这篇文章
跟自己的诉求有什么关系。

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 关键词/短语查询有结果 | 输入技术名词能命中对应文章 | ⏳ T1.1.3 |
| 中文/英文都能查 | 中文查询命中中文文章，英文查询命中英文文章 | ⏳ T1.1.3 |
| 跨语言查询（进阶，Phase 1 起） | 中文问英文文章内容也能命中 | ⏳ 待 Phase 0B 验证是否值得做 |
| 没有相关文章时不瞎推荐 | 查询在博客里确实没有对应内容时，页面要说明"没有找到"，不能硬凑结果 | ⏳ T1.1.3 |
| 结果不被单篇文章刷屏 | 同一篇文章不会在结果列表里重复出现多次 | ⏳ Phase 1 起需要（T1.3.3 文章级聚合） |

## 二、索引跟得上文章更新（Phase 2 起）

新文章发布后，不需要人工手动触发，搜索里就能找到它；文章删除/改名后，旧的搜索结果
不会指向一个不存在的页面。

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 新文章自动可搜 | 发布流程跑完之后，短时间内新文章可被搜到 | ⏳ Phase 2（T1.4.1） |
| 删除的文章不再出现 | 文章下线/删除后，搜索结果里不再包含它 | ⏳ Phase 2（T1.4.1/T1.4.2） |

## 验收时怎么判断「好用」

1. 用 Phase 0A 整理的 20–30 条评测查询手动跑一遍，多数（不要求 100%）能在前 5 条结果里
   看到符合预期的文章。
2. 中文/英文/跨语言几类查询都测过，不只测中文。
3. 不出事故：搜索页面报错、结果链接失效、误报"没有结果"都算失败案例，需要记录下来。
4. 是否值得从 Phase 0A（纯关键词）升级到 Phase 1（语义检索），由 T1.2.2 依据 Phase 0B 的
   离线对比数据人工拍板，不是凭感觉决定。
