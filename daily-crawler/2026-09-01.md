## S1. PaymentOps Agent：最值得直接做成 Vertical Pack 的场景

Cashfree 的 Relay 最近从 beta 推向全部商户，定位非常直接：不是提醒商户“这里有失败支付”，而是让 Agent **直接执行支付运营流程**，包括失败支付重试、弃单追回、COD 确认、失败订阅处理和争议提交。Cashfree 官方强调关键动作仍保留人工审批：**涉及资金移动或主动联系客户时要求确认**，所有动作留下记录。

更有意思的是商业模式：Relay 当前免费开放，外部报道显示 Cashfree 计划后续探索 **outcome-based pricing**。这和我们前几天讨论的 AI Work Unit 又往前走了一步：不只是“处理了多少任务”，而是可以按 **追回多少收入、减少多少损失** 收费。

### 为什么值得 SME 关注

支付运营特别适合 Agent 化，因为它满足三个条件：

1. 高频、重复、规则相对明确；
2. 延迟会直接造成收入损失；
3. 结果天然可量化，例如 recovered GMV、failed payment recovery rate、dispute win rate。

### 建议开源组件

`payment-ops-core`

```text
Payment Event
   ↓
Classify
   ↓
Workflow State Machine
   ↓
Policy / Approval
   ↓
Execute
   ↓
Audit Trail
   ↓
Outcome Meter
```

开源层不要碰真正的支付清算本身，重点做通用的 **状态机、审批、审计、异常升级、结果计量接口**。

### 可收费

- Ecommerce Payment Recovery Pack
- Subscription Dunning Pack
- COD Confirmation Pack
- Dispute Assistant
- Payment provider / ERP Connector
- 按 recovered revenue 或 business outcome 收费

## S2. Headless Business Capabilities：以后 Agent 接的可能不是 API，而是“企业能力”

Salesforce 最近扩展 Headless 360，核心思想非常值得借鉴：普通 MCP Server 暴露 API；它希望暴露的是 **trusted business capabilities**。Agent 调用能力时，不需要把 Salesforce 里已有的身份、权限、字段关系、Workflow、Validation Rule 和 Governance 再用 Prompt 重写一遍。

这解决了企业 Agent 很容易被低估的一类成本：

> “能调用 CRM API” ≠ “懂这家公司的 CRM 应该怎么操作”。

真正困难的是业务规则。

### 对 SME AI Node 的启发

以后 Connector Layer 可以分成两层：

```text
Raw Connector
API / DB / Browser
      ↓
Capability Layer
"create_quote"
"qualify_lead"
"approve_discount"
"reorder_inventory"
      ↓
Agent / Skill / Workflow
```

也就是说，**不要让每一个 Agent 自己拼十几个 CRUD API。** 应该把稳定的业务动作封装成 metadata-aware capability。

### 建议开源组件

`capability-gateway`

至少定义：

```text
name
purpose
input_schema
output_schema
permissions
business_rules
approval_policy
risk_level
audit_schema
```

然后可以通过 MCP 暴露，但内部不绑定 MCP，未来也可以接其他协议。

### 可收费

- 私有 ERP / CRM Capability Pack
- 老系统 Browser Capability
- 企业 Policy / Validation 映射
- Managed MCP / Capability Gateway
- FDE 定制业务能力

## S3. Agent Security：权限正确，不代表动作合理

Operant 最近推出 Semantic Firewall，值得关注的点不是具体产品，而是一个更成熟的安全抽象：**Agent 的 Tool Call 即使技术上有权限，也可能在语义上越权。**

例如 Sales Agent 有 `crm.read`：

- 读取一个客户 → 合理；
- 一次导出 50 万客户 → 技术上可能同一个 API 权限，但语义风险完全不同。

Operant 把这层拆成 Tool Intent、Code Intent、Data Intent、Scope Guard，并在执行前返回 `allow / block / redact`。它还允许用自然语言表达政策，例如“PII 不得离开这个 workspace”。

### 对 SME AI Node 的启发

前面已经设计了 Permission、Autonomy Ladder 和 Context Firewall，现在应该再加最后一层：

```text
Identity
   ↓
Permission
   ↓
Context Firewall
   ↓
Agent Plan
   ↓
Action Firewall   ← 新增
   ↓
Tool / API / Browser
   ↓
Audit
```

**Permission 判断“你能不能调用”；Action Firewall 判断“你这一次到底想干什么”。**

### 建议开源组件

`action-firewall`

第一版不需要复杂模型，可以从规则 + risk classification 开始：

- scope guard
- bulk-action guard
- sensitive-data egress guard
- destructive action guard
- destination allowlist
- allow / block / redact / require-approval

### 可收费

- Finance / HR / Legal Policy Pack
- 企业策略管理 UI
- 安全事件审计
- Compliance Mapping
- Managed Agent Security

## A1. 今日 GitHub 值得拆：Omni —— 公司级 Agent 的底座正在变得很清晰

GitHub: https://github.com/getomnico/omni

Omni 是 Apache-2.0、self-hosted 的 company-wide AI agent。仓库在 **2026-08-31** 仍有连续提交，目前约 765 stars。它同时整合：

- Gmail / Google Drive / Slack / Jira / Confluence / HubSpot 等 Connector；
- 权限感知的 Company Context；
- BM25 + pgvector Hybrid Search；
- Agent Runtime；
- Sandbox Code Execution；
- 多模型 Provider；
- MCP / Connector SDK；
- Docker Compose / Terraform 部署。

8 月 31 日最新提交之一还加入了 **PostgreSQL-backed durable task queue**，另外连续修复了模型 token usage 统计。这两个细节很值得注意：一个真正长期运行的企业 Agent，最后一定会遇到 **任务持久化 + 成本计量**，而不是只有 Chat UI。

### 为什么值得研究而不是直接 Fork

它与 SME AI Node 的底层方向高度重合，可以作为架构 reference implementation。但它更偏通用 company assistant，我们真正应该建立差异的是：

```text
Omni-like Foundation
        +
SME Autonomy / Security
        +
Business Capability Layer
        +
Vertical Operating Packs
        +
Outcome / ROI Meter
```

### 可开源沉淀

不必重新造完整 Omni，可以重点吸收/兼容：

- Company Context interface
- Connector isolation pattern
- permission-aware retrieval
- durable task queue
- model usage accounting

### 可收费

- 一键 SME 部署
- 私有 Connector
- 数据权限迁移
- Local model optimization
- Backup / observability / SLA
- Vertical Pack
