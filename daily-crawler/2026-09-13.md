## S1 — Voice-to-Record: 别再让一线员工“先说一遍，再填一遍”

### Signal

Kintone’s **September 13, 2026** update introduces **AI Voice Data Entry** for its iOS mobile app. A user can speak naturally, after which AI transcribes the speech, decides which record fields the information belongs in, reshapes the content to match those fields, and lets the user review it before saving.

Kintone explicitly gives two examples that map well to SME operations:

- sales meeting reports while outside the office;
- inspection records created on site.

Sources:

- Kintone September 2026 update: <https://jp.kintone.help/k/en/update/main/2026/09>
- Kintone Thailand: <https://www.kintone.com/th-th/>

### Enterprise pain

For many SMEs, the problem is not that they lack a CRM/ERP/database. The problem is that **the data never gets entered consistently**.

Common patterns:

- salesperson finishes a customer visit but postpones CRM entry;
- technician performs an inspection and later reconstructs the report from memory;
- restaurant/store staff verbally report stock or equipment issues but nobody structures them;
- construction/site workers send photos and voice messages into LINE, leaving business systems stale;
- the owner eventually becomes the human ETL pipeline.

Traditional voice transcription solves only half the problem. A transcript is still another blob of text.

The useful product primitive is:

> **Speech → structured business record → validation → human confirmation → system-of-record write-back.**

### Why it is worth tracking

This is a good example of AI becoming a **write interface to business systems**, not just a chat interface.

For SME adoption, reducing the cost of **producing clean operational data** may be more valuable than building another RAG layer over dirty, incomplete data.

It also fits Thailand and Southeast Asia well because many frontline workflows are already voice-heavy and mobile-first.

### Free / open-source component: `voice-to-record-schema`

A framework-neutral v0.1 could accept free-form speech/text plus a target JSON Schema:

```text
Voice / free-form text
        ↓
Transcription
        ↓
Schema-aware extraction
        ↓
Field normalization
        ↓
Validation / confidence
        ↓
Human review as a diff
        ↓
Connector write-back
```

Suggested primitives:

- JSON Schema / form definition input;
- field-level extraction and confidence;
- date / number / currency normalization;
- required-field detection;
- “unknown / needs clarification” state rather than hallucinated values;
- proposed-record diff before commit;
- provenance back to transcript/time span;
- pluggable STT: cloud or local;
- multilingual vocabulary packs;
- adapter interface for Kintone / HubSpot / Zoho / Odoo / custom ERP;
- audit event after write-back.

A Thai-focused reference pack could support common sales, field-service and inspection terminology.

### Paid service

- Kintone / Odoo / CRM / ERP connector implementation
- Thai/English industry vocabulary tuning
- Private/local speech pipeline
- Field-service / construction / hospitality record packs
- Workflow redesign and FDE implementation
- Managed monitoring of extraction quality and failed records

### Content recommendation

**Best Blog:**

> **《别再让一线员工填表：把语音直接变成 ERP/CRM 结构化记录》**

**Best short video:** say one messy 30-second customer-visit note in Thai/English, then show it becoming `customer / date / issue / amount / next_action` fields and waiting for one-tap approval.

## S2 — OSS Radar: Olares 把“本地 AI”做成一台可运营的 Appliance

### Signal

The open-source project **Olares** describes itself as a personal cloud OS for always-on AI agents and local LLMs, built on Kubernetes and intended for individuals and small teams. It combines compute, storage, networking, applications, private access and local AI in one system.

The repository currently highlights:

- one-click local AI apps and models;
- local files plus SMB/NFS/cloud storage;
- backup management;
- private VPN / reverse proxy / access control;
- GPU/accelerator pooling across nodes;
- self-hosted workspaces and agentic applications;
- Linux plus installation paths for Windows, macOS and Raspberry Pi.

The project published **v1.12.7-20260912 as a prerelease on September 12**, showing that the stack is actively shipping.

Sources:

- Repository: <https://github.com/beclab/Olares>
- Latest prerelease: <https://github.com/beclab/Olares/releases/tag/1.12.7-20260912>

### Enterprise pain

A local-first SME AI deployment often becomes an accidental infrastructure project:

```text
Ollama / model server
+ Docker / Kubernetes
+ storage
+ user accounts
+ remote access / VPN
+ secrets
+ backup
+ dashboards
+ app updates
+ GPU management
+ Agent runtime
```

A 10–50 person business does not want to maintain this stack. It wants something closer to a NAS or router: **install, configure, monitor, update, recover**.

### Why it is worth tracking

The important signal is not that Olares itself must become our product. It is that **“AI appliance / AI NAS” is becoming a plausible product category**.

This aligns strongly with a local-first SME AI Node: instead of selling customers a pile of containers, sell an operational profile with known hardware requirements, backup policy, model routing, health checks and approved applications.

We should avoid forking an entire OS unless necessary. A better layer for us is a portable profile that could target Olares first but remain compatible with another runtime later.

### Free / open-source component: `sme-ai-appliance-profile`

Define what a production-ready SME node should expose regardless of underlying OS:

```yaml
node:
  identity: branch-office-01
  storage:
    backup: daily
    retention_days: 30
  models:
    local: [small-fast, private-general]
    cloud_escalation: true
  access:
    vpn_only: true
    admin_mfa: true
  required_services:
    - model_gateway
    - company_memory
    - connector_runtime
    - audit_log
    - scheduler
  health:
    disk_threshold: 80%
    backup_freshness_hours: 30
    model_probe: true
```

Reference implementation can provide:

- one-command health report;
- backup / restore verification;
- model and GPU inventory;
- approved app/agent manifest;
- secrets and VPN checks;
- local → cloud fallback profile;
- export/migration bundle so the customer is not locked into one appliance runtime.

### Paid service

- preconfigured mini-PC / workstation / Mac mini deployment
- installation and company migration
- managed backup and disaster recovery
- security hardening and remote support
- managed upgrades
- local model benchmarking and capacity planning
- vertical operating packs for hotel, restaurant, trading company, accounting firm

### Content recommendation

**Best Blog:**

> **《SME 需要的可能不是 AI Server，而是一台“AI NAS”》**

Use Olares as the open-source signal, then explain the category: **business data + local models + agents + connectors + VPN + backup + upgrade lifecycle** in one manageable node.

## S3 — Shadow Agent Inventory: 治理 Agent 的第一步不是 Policy，而是“先找到它们”

### Signal

A recent report covered by TechRadar, based on Reco telemetry, argues that a large share of AI tools are operating without IT oversight. The report claims **80% of AI tools** in its sample operate outside IT oversight and that **62% of AI agents** observed can both reach local data and connect to the Internet. These are vendor-study figures and should not be generalized to all companies, but they point to a real operational problem: AI software spreads through extensions, CLIs, MCP servers and employee-installed tools faster than traditional software inventory processes.

Open source is already moving into this gap. **StepSecurity Dev Machine Guard** can inventory AI CLI tools, AI agents, local AI frameworks, MCP server configurations and IDE extensions across macOS, Windows and Linux, and outputs JSON/HTML locally. Its community scanning engine is Apache-2.0 and works without uploading local data.

Dataiku is attacking the same problem at the enterprise control-plane level: its Agent Management product says it can connect to agents across platforms, automatically scan/inventory them, then track business KPIs, drift and governance from one place.

Sources:

- StepSecurity Dev Machine Guard: <https://github.com/step-security/dev-machine-guard>
- Dataiku Agent Management: <https://www.dataiku.com/product/agent-management>
- TechRadar summary of the Reco study: <https://www.techradar.com/pro/almost-all-ai-tools-are-now-running-with-no-oversight-from-it-putting-companies-in-the-firing-line>

### Enterprise pain

A small company can very quickly accumulate:

- ChatGPT / Claude / Gemini accounts;
- Cursor / Claude Code / Codex / Copilot;
- local Ollama / LM Studio models;
- random MCP servers;
- browser extensions;
- n8n / Zapier / custom agents;
- LINE / Slack bots;
- API keys copied into local config files.

The owner usually cannot answer four basic questions:

1. What AI tools are installed?
2. Who owns them?
3. What company data can they read?
4. What external actions can they take?

Yesterday’s `agent-egress-policy` addresses how an Agent is allowed to act. Today’s missing prerequisite is **discovery and inventory**.

### Free / open-source component: `sme-ai-inventory`

Do not rewrite all scanners. Build a thin aggregator around projects such as Dev Machine Guard plus parsers for common business automation configs.

Normalized asset model:

```json
{
  "asset": "claude-code",
  "device": "sales-mac-03",
  "owner": "unknown",
  "type": "ai_cli",
  "mcp_servers": 4,
  "local_data_access": true,
  "network_access": true,
  "credential_sources": ["env", "keychain"],
  "approved": false,
  "risk": "high"
}
```

v0.1 output:

- local JSON / HTML inventory;
- Agent / MCP / extension / model / automation discovery;
- owner and business-purpose annotation;
- “approved / unknown / prohibited” state;
- data-access and network-access indicators;
- credential-surface metadata without collecting secrets;
- diff between last scan and current scan;
- recommended remediation;
- optional export into the SME AI Node policy layer.

### Paid service

- multi-device central dashboard
- managed allowlists and policy
- monthly AI security posture report
- MCP / agent remediation
- MSP-style security service for SMEs without internal IT
- mapping discovered assets into egress / spend / identity policies

### Content recommendation

**Best Blog:**

> **《你公司到底装了多少个 AI Agent？治理之前，先把 Shadow AI 找出来》**

**Video:** scan one developer/employee Mac, show Claude Code, Codex, MCP servers and extensions appearing in a single AI asset inventory — without reading user files or API keys.

## S4 — Deterministic Agent Flow: 关键业务不要让 ReAct Agent 自由发挥

### Signal

Dataiku’s current **Structured Visual Agents** documentation is a useful architecture signal. Instead of relying only on a generic tool-calling loop, it supports a transparent sequence/graph of blocks with **deterministic logic**, state/scratchpad, branching, loops, tool calls and exit conditions. Dataiku’s agent APIs also support explicit human approval before configured tool calls proceed.

Sources:

- Structured Visual Agents: <https://doc.dataiku.com/dss/latest/agents/structured-visual-agents/index.html>
- Dataiku agent developer guide: <https://developer.dataiku.com/latest/concepts-and-examples/agents.html>

### Enterprise pain

ReAct-style autonomy is excellent for research and exploratory work. It becomes uncomfortable when an SME needs predictable behavior for:

- quotation approval;
- refund processing;
- procurement;
- invoice reminders;
- booking confirmation;
- credit checks;
- customer escalation;
- payroll / HR actions;
- any workflow where one missing step creates real cost.

A business process often has **mandatory steps** that the model should not be allowed to skip because it “reasoned” differently this time.

### Why it is worth tracking

The mature pattern is likely:

> **Deterministic process outside; probabilistic intelligence inside bounded nodes.**

Example:

```text
Receive request
   ↓
[LLM] classify intent
   ↓
[Rule] amount > threshold?
   ├─ yes → Human approval
   └─ no
   ↓
[Tool] fetch account / order
   ↓
[LLM] draft decision explanation
   ↓
[Rule] mandatory evidence present?
   ├─ no → request missing evidence
   └─ yes
   ↓
[Tool] commit
   ↓
[Verify] read-back + audit
```

The LLM is used where ambiguity is useful; the state machine owns what **must** happen.

### Free / open-source component: `bounded-agent-flow`

A tiny framework-neutral spec could define:

- typed state;
- `llm`, `tool`, `rule`, `approval`, `handoff`, `verify` nodes;
- mandatory tool calls;
- explicit entry/exit conditions;
- retry budget per node;
- timeout / compensation action;
- human approval checkpoints;
- evidence requirements;
- deterministic replay for testing;
- outcome metrics and audit trace.

Reference packs:

1. customer refund;
2. quotation → manager approval → send;
3. supplier order;
4. booking change;
5. overdue invoice follow-up.

### Paid service

- translating company SOPs into bounded flows
- vertical workflow packs
- ERP/CRM/POS integration
- workflow testing/evaluation
- change management and versioning
- FDE implementation and ongoing SLA

### Content recommendation

**Best Blog:**

> **《关键业务别让 ReAct Agent 自由发挥：SME AI 应该像工作流一样可控》**

**Demo:** run the same refund request through a free-form Agent and a bounded flow; show how the bounded version cannot skip evidence, approval or post-write verification.

```text

        ↓

        ↓

        ↓

        ↓

        ↓
```

Reference demo:

> “I met ABC Hotel this morning. They need 30 units next month, budget around 120,000 baht. Send the revised quote Friday and remind me Thursday afternoon.”

Output:

```json
{
  "customer": "ABC Hotel",
  "meeting_date": "2026-09-13",

  "next_action": "Send revised quotation",
  "next_action_date": "2026-09-18",
  "reminder": "2026-09-17 afternoon"
}
```

The model should propose, not silently commit. The user reviews the diff, then the adapter writes to CRM/Kintone/Odoo.

## Product thesis update

The SME AI Node now looks less like a chatbot platform and more like a **small-business operating appliance**:

```text
Natural Input
Voice / Chat / File / Event
        ↓
Structured Business Data
        ↓
Company Context + Memory
        ↓
Business Capability / Connector
        ↓
Bounded Agent Flow
        ↓
Identity + Permission + Spend + Egress Policy
        ↓
Local AI Appliance / Cloud Escalation
        ↓
Human Approval + Evidence + Audit
        ↓
Business Outcome / ROI

Cross-cutting:
AI Asset Inventory / Health / Backup / Upgrade / Security
```

The key product shift is:

> **Do not ask SMEs to become AI infrastructure teams. Give them natural input, controlled workflows and an appliance that can be operated like business infrastructure.**

That creates a clean open-core path:

- **Free / open:** schemas, profiles, inventory, bounded-flow spec, reference connectors.
- **Paid:** deployment, hardware, industry packs, connectors, governance, backup/security, FDE and managed operations.
