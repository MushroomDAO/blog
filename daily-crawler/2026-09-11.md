## S1 — Embedded AI Agent Store: SMEs may “hire” packaged agents inside the software they already pay for

### Enterprise pain

Small businesses rarely have the staff or time to choose models, configure MCP servers, connect five SaaS products, define permissions and monitor workflows. Even when an agent is technically capable, integration cost and operational complexity kill adoption.

### Why it matters now

On **September 10**, PayU launched **Agent HQ** for Indian SMB merchants at Global Fintech Fest. The important part is not the branding; it is the distribution model:

- the agent store is built directly into the existing PayU merchant dashboard;
- merchants can choose agents for growth or operations with a no-code / zero-integration setup;
- examples include transaction follow-ups, chargeback reconciliation, refund escalation and settlement workflows;
- merchants can select how frequently an agent runs, monitor its activity, and receive outputs through email or WhatsApp;
- agents operate within merchant-defined limits.

This is a strong confirmation that the SME market may adopt AI through **existing systems of record and service providers**, not by buying a separate generic “AI employee” platform.

Sources:

- Economic Times, Sep 10: https://economictimes.indiatimes.com/ai/ai-insights/gff-2026-payus-new-ai-agent-store-aims-to-change-how-smbs-run-businesses/articleshow/134004233.cms
- CXO Today launch coverage: https://cxotoday.com/media-coverage/meet-payu-agent-hq-merchants-own-ai-agents-team-built-to-power-their-agentic-commerce-journey-end-to-end/

### Free open-source component

**`agent-catalog-spec`**

A portable manifest for a packaged business agent:

```yaml
id: payment.reconciliation-agent
vertical: merchant
outcome: reconcile_payment_exceptions
trigger:
  type: schedule
  cadence: daily
required_capabilities:
  - payments.read
  - settlements.read
allowed_actions:
  - reconciliation.propose
  - case.create
risk: medium
approval: exception_only
budget:
  monthly_usd: 20
success_metrics:
  - exceptions_resolved
  - human_minutes_saved
outputs:
  - dashboard
  - email
  - whatsapp
```

The useful open-source layer is not another marketplace UI. It is a **vendor-neutral contract** describing what an agent does, what data/actions it needs, how risky it is, how often it runs, how humans approve it, and how success is measured.

## S2 — Know-Your-Agent: delegated commerce needs an identity and mandate layer

### Enterprise pain

Once AI agents can buy, book, refund, subscribe or pay on behalf of a customer, merchants face a new problem: **who exactly is this agent, who authorized it, what is it allowed to do, and can the transaction be trusted?**

Traditional user login is not enough because the actor executing the transaction may be software acting under a delegated mandate.

### Why it matters now

On **September 10**, Visa, Mastercard and Ant International announced work on a common **Know-Your-Agent interoperability framework**. The goal is to let card networks, wallets, agent platforms and marketplaces recognize trusted AI agents while retaining their own approval and risk systems.

The proposed framework builds on Visa Trusted Agent Protocol, Mastercard Verifiable Intent and Ant International’s Agentic Mobile Protocol, and is being developed through **BuildFin.ai**, convened by the Monetary Authority of Singapore.

This is an important infrastructure signal: agentic commerce is moving from “can the model click checkout?” to **identity + intent + delegation + risk + audit**.

Source:

- Reuters, Sep 10: https://www.reuters.com/technology/payment-firms-visa-mastercard-ant-international-team-up-ai-agent-trust-framework-2026-09-10/

### Free open-source component

**`agent-trust-envelope`**

A simple, payment-neutral delegated-authority object:

```yaml
agent_id: agent_abc
issuer: merchant-ai.example
principal_id: customer_123
mandate:
  purpose: purchase_office_supplies
  max_amount: 500
  currency: THB
  merchant_scope:
    - approved_vendor_1
  expires_at: 2026-09-11T18:00:00+07:00
transaction_intent:
  item_hash: sha256:...
  amount: 420
  nonce: 8f2...
approval_policy: auto_under_limit
audit_uri: evidence://txn/123
signature: ...
```

It should be compatible with different payment providers rather than trying to replace their protocols.

### Potential paid service

- merchant-side Agent Trust Gateway
- delegated-spend policy management
- verification / certification of third-party commerce agents
- payment-provider adapters
- fraud / anomaly scoring for agent-originated transactions
- compliance and audit reports

### Content recommendation

**Blog:** `When an AI Agent pays you, how do you know who authorized it?`

**Short video:** visually explain the difference between **User Identity → Agent Identity → Delegated Intent → Payment Authorization**.

This also extends the earlier `agent-spend-policy`: spend policy controls **what the agent may spend**; the trust envelope proves **who the agent is and under whose authority it is acting**.

## S3 — WebMCP: the web itself is becoming an Agent capability layer

### Enterprise pain

Many SME workflows still live in ordinary web apps. Today an agent generally has two bad choices:

1. wait for a backend API/MCP integration, or
2. drive the UI through brittle browser automation.

The first has integration cost; the second breaks whenever the page changes.

### Why it matters now

A new **WebMCP draft** was published by the W3C Web Machine Learning Community Group on **September 9**. It allows a web application to expose JavaScript-based tools directly to an AI agent through browser APIs.

The important distinction from conventional backend MCP is that WebMCP can reuse the browser’s existing **authenticated user session, origin security model and visible human context**. The specification remains an experimental Community Group draft — **not a W3C Standard yet** — so it should be treated as an emerging interface rather than a production dependency requirement.

The open-source **MCP-B / WebMCP** ecosystem is already building polyfills and bridges. Its packages were updated through September 9–10 and include React and TypeScript tooling for exposing website functions to agents.

Sources:

- W3C Community Group draft: https://webmachinelearning.github.io/webmcp/
- MCP-B / WebMCP GitHub organization: https://github.com/WebMCP-org

### Free open-source component

**`webmcp-business-kit`**

Goal: allow an SME SaaS or internal web app to mark existing UI/business functions as agent-callable capabilities without building a separate agent backend first.

Initial pieces:

- React hook / vanilla JS helper for registering tools
- standard annotations for `read-only / consequential / irreversible`
- permission + human confirmation wrapper
- audit event emitter
- capability naming convention shared with backend MCP
- fallback adapter when native browser support is absent

Example concept:

```ts
registerBusinessCapability({
  name: "invoice.send",
  risk: "high",
  consequential: true,
  requireConfirmation: true,
  handler: sendInvoice,
});
```

### Potential paid service

- “Agent-ready website / SaaS” upgrade service
- WebMCP audit and migration
- legacy ERP frontend adapters
- managed capability registry
- enterprise security policy pack
- FDE conversion of existing workflows into WebMCP + backend MCP hybrids

## S4 — Human-Agent Control Plane: the missing primitive is often a shared queue, not more autonomy

### Enterprise pain

SMEs cannot allow every agent to run fully autonomously, but “ask me in chat whenever something happens” also does not scale. Once multiple agents operate continuously, humans need a common place to see:

- what is running,
- what is blocked,
- what needs approval,
- what finished,
- who owns the next step.

### Why it matters now

**AgentRQ** is a useful open-source project to watch. It is an Apache-2.0 human-in-the-loop task manager that exposes task state to agents through MCP and connects to Claude Code plus ACP-compatible agents. It includes workspaces, task queues, real-time updates, permission requests, a global supervisor, Slack integration and self-hosting.

The project released **v0.5.21 on September 10**; the immediately preceding releases added clearer connected-agent/session state. The repository currently has roughly **1.1k stars**, showing enough developer attention to merit tracking without assuming it is already production-proven for SME deployments.

Sources:

- GitHub: https://github.com/agentrq/agentrq
- Releases: https://github.com/agentrq/agentrq/releases

### Free open-source component

Rather than cloning AgentRQ, define a small **`human-agent-queue` contract** that any task manager can implement:

```yaml
work_id: work_483
agent: finance-agent
state: waiting_for_human
requested_action: refund.approve
risk: high
sla_minutes: 30
assignee: owner
context_uri: evidence://refund/483
allowed_responses:
  - approve
  - reject
  - request_more_evidence
resume_token: ...
```

Core states:

`queued → running → waiting_for_human → resumed → completed / failed / cancelled`

### Potential paid service

- deploy AgentRQ or another compatible control plane for a customer
- Slack / LINE / email approval adapters
- escalation rules and SLA setup
- multi-agent operations dashboard
- managed 24/7 exception queue
- analytics on human-intervention rate and agent autonomy progression

### Content recommendation

**Blog:** `Your AI employees need an inbox: why human approval should be a queue, not a chat message`

**Demo:** three agents working in parallel; one completes automatically, one asks for a refund approval, one escalates missing data.

## Infrastructure Radar

### Salesforce: Enterprise AI Harness + AI Control Plane

On **September 10**, Salesforce described a six-part architecture:

1. Trusted Context
2. Trusted Agency
3. Trusted Action
4. Trusted Governance
5. Trusted Security
6. Trusted Models

It also announced an AI Control Plane covering agent discovery/registration, identity and policy, lifecycle, evaluation, behavior/outcome observability and cost control across Salesforce and third-party AI.

Source: https://www.salesforce.com/news/stories/enterprise-ai-harness/

**Why it matters to us:** this is close to the architecture the daily research has independently converged on. For SMEs we should not copy the enterprise stack; we should offer a **small, opinionated profile** of the same primitives.

### Red Hat AI 3.5: AI infrastructure becomes an accountable shared service

Red Hat AI 3.5, announced September 9, adds:

- EvalHub for model / application / agent evaluation and safety evidence
- per-user token showback
- model and agent observability
- controlled model rollout
- fair-share / priority-aware GPU scheduling
- integrated guardrails for malicious tool calls
- agent templates and local EvalHub development

Source: https://www.redhat.com/en/about/press-releases/red-hat-puts-safety-and-observability-core-enterprise-ai-red-hat-ai-35

**SME takeaway:** do not reproduce OpenShift. Borrow the operating model: every shared AI service needs **evaluation before promotion, cost attribution, health visibility, rollback and evidence**.

## Product Thesis Update

Today’s signals make the SME AI stack look increasingly like this:

```text
Existing SME Distribution Surface
(bank / payment / ERP / POS / telecom / SaaS)
        ↓
Agent Catalog / Vertical Packs
        ↓
Business Capabilities
(API / MCP / WebMCP / UI / Voice)
        ↓
Company Context + Memory
        ↓
Identity + Delegated Intent + Policy
        ↓
Human-Agent Queue / Approval
        ↓
Execution + Evidence + Verification
        ↓
Evaluation + Cost / ROI + Continuous Improvement
```

The durable opportunity is shifting away from “build one clever Agent” toward **making AI work installable, governable, distributable and commercially supportable for ordinary businesses**.
